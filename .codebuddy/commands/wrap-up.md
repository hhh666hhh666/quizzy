# 收尾自检

按顺序做完 1–5，最后按第 6 节的模板回复。**任何一步发现东西都要真的落盘，不是只在回复里提一句。**

## 1. 把改动摆出来

```bash
git status --porcelain
```

这是本次「改了什么」的唯一真值，后面所有判断都基于它。

## 2. 捞出「提到过但没做的事」（最关键的一步）

扫描本次对话，逐条找下面三类，每条给出处置：

- **A 类 · 被推迟的决定**：出现「以后 / 回头 / 下次 / 暂缓 / 先不 / 还没定 / 看情况 / 再说 / 不在本次范围」
- **B 类 · 被识别但没修的问题**：写了风险却没结论、给了选项没给推荐、代码里新加了 `TODO`/`FIXME`、脚本里留了手动步骤
- **C 类 · 说过但没验证的假设**：「应该是这样」「大概率是」「估计是」这类没核实的话

| 情况 | 处置 |
|------|------|
| A/B 类，且现在确实定不了（缺信息、缺环境） | 写进 `docs/todo/`：同主题有文件就追加，没有就新建 `docs/todo/YYYY-MM-DD-TODO-<主题>.md`，并更新索引表 |
| A/B 类，但其实现在就能定 | **别拖延**：直接做掉或当场给推荐，然后写 ADR + 「已定，不用再想」表一行 |
| C 类 | 要么现在核实（跑命令/读代码，最多几分钟），要么写进 TODO 并标注「待验证」 |
| 纯噪音（无决策含义） | 丢弃——但要在报告里写明「XX 已判断为噪音，不落 TODO」 |

> 判据：三个月后自己读到这段对话会问「我当时到底决定了吗」——那就必须落 TODO。

## 3. 补文档与引用

对着第 1 步的文件清单，逐项走 `docs-sync` 规则的「改动 → 该去哪儿改」表。特别检查：

- 有没有**移动/删除/重命名**过的文件 → `git grep -n '<旧名>'`，注释和脚本里的引用也要改
- 有没有新加/改了 `scripts/*.sh`、`.github/workflows/*.yml`、环境变量 → `docs/operations/` 下三份要不要动
- 有没有新的结构性决策 → 需要补 ADR 吗

## 4. 跑断链检查

```bash
bash scripts/check-doc-links.sh
```

红了就修到绿，**不要把红着的结果留在工作区**。

## 5. 提议 commit

按 Conventional Commits 切分（`feat:` / `fix:` / `docs:` / `ci:` / `chore:` / `refactor:`），一次改动一个主题。
**不要替用户 commit**，只给出建议的 commit 列表。

## 6. 回复模板

```markdown
## 本次改了
- `<文件>`：<一句话>

## 未决事项
- 新增/更新 `docs/todo/YYYY-MM-DD-TODO-<主题>.md`：<一句话>
- （或：本次无未决事项）
- 判断为噪音、不落 TODO：<XX，因为……>

## 文档同步
- `<文档>`：<改了什么 / 为什么>
- check-doc-links：通过

## 建议 commit
1. `<type>(<scope>): <标题>`
```
