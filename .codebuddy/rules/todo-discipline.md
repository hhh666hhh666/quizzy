# 未决事项落盘

对话会关、上下文会被压缩，只有文件不会。**任何还没定的事，必须在本次回复结束前**变成 `docs/todo/` 下的文件——在回复里说一句「以后可以优化」不算完成。

## 触发信号（命中任一即视为未决）

- **措辞**：以后 / 回头 / 下次 / 暂缓 / 先不 / 再说 / 还没定 / 看情况 / 待确认 / 不在本次范围
- **形态**：给了选项表却没给推荐；写了风险（⚠️）却没给结论；识别出可改进却没改；代码里冒出 `TODO`/`FIXME`；脚本里留了手动步骤
- **用户说**「这条先记着」

**不算未决**，别浪费文件：已经拍板的 → 走 ADR；能从代码查到的事实 → 不写（ADR 0006）。

## 落盘动作

1. **先读 `docs/todo/README.md` 索引表**。同主题已有文件就**追加到它的小节里**，不要新建。现有主题：数据库备份 / 运行与运维 / 镜像分发。
2. 确实要新建，才用 `docs/todo/YYYY-MM-DD-TODO-<主题>.md`。日期是**创建日期**，之后怎么改都不改名；主题写中文。
3. 文件头固定三段：

   ```markdown
   # 待办：<主题>

   创建：YYYY-MM-DD · 状态：待办 · 优先级：高|中|低

   ## <问题一句话>
   现状 + 为什么现在定不下来 + 可选方案（写了方案就要写倾向，别让用户空手选）
   ```

4. **必须回 `docs/todo/README.md` 索引表补一行**：`| [文件名](./文件名) | 主题 | 待办 | 优先级 |`。状态变了也要回来改。
5. **反向处理一次**：本次真正拍板的结论 → 过程原文留 `docs/decisions/`，结论卡片进 `docs/adr/00NN-*.md`（编号递增，Status / Considered Options / Consequences，**只追加不改**），并在索引页的「已定，不用再想」表加一行，防止以后重新纠结。

## 每次回复结束前自检

- 我这次有没有「可以去改但没改」的东西？
- 有没有给用户留了选择却没说推荐哪个？
- 有没有把事推到以后——那是用户同意推迟的，还是我自己省事？
- 新落的文件进索引表了吗？
- 我有没有在 README / CHANGELOG / ADR / 设计文档正文里开第二份待办清单？（**违规**，见 `docs/README.md` 的纪律，删掉并指回 `docs/todo/`）

完整收尾流程用 `/wrap-up`。
