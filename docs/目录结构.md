# 文档目录结构

> 这是 quizzy `docs/` 的**现状图示**：只画层级与各文件职责，一句话一条。
> 谁有内容、谁对谁是真相源，以[文档地图](./README.md#文档地图)为准——那张表才是权威索引，这里只是把同一批文件画成树。
> 与文件系统或 [README.md](./README.md) 不一致时以它们为准，并顺手把本文件改回。

## 目录树

```
docs/                               # 文档根：与代码同仓、同 PR 评审（Docs as Code）
├── README.md                       # 文档地图：路径 / 用途 / 读者 / 真相源 四列表，只回答「东西在哪」
├── adr/                            # 决策结论卡片，一条一卡、只追加不改
│   └── NNNN-*.md                   # 编号递增、只追加不改；0006 是格式范本
├── decisions/                      # 决策过程日志：grill 问答原文、被否选项、当时的纠结
│   └── *.md                        # 5 篇，按主题命名；records-and-glossary 含 ADR 收录标准
├── design/                         # 设计文档，按主题拆分
│   ├── API.md                      # 怎么看真实接口 + 通用约定（刻意不维护 endpoint 表）
│   ├── 判分与业务规则.md           # 判分 / 会话 / 错题本 / 规则卷抽题语义
│   ├── 前端.md                     # 页面流、路由、状态与 API 边界
│   ├── 导入导出.md                 # Excel / JSON 契约形状与容错语义
│   └── 数据模型.md                 # 实体关系、可见性、生命周期、历史一致性
├── development/                    # 开发协作
│   └── contributing.md             # 分支 / 提交 / PR 约定与文档纪律
├── operations/                     # 运行与运维
│   ├── backup.md                   # 备份现状、手动跑一次、恢复（未演练）
│   ├── configuration.md            # 配置从哪来、改了要重启什么
│   ├── deployment.md               # 上线路径、上线前检查、回滚
│   └── runbook.md                  # 应急预案：按症状查处置步骤
├── requirements/                   # 范围约束
│   └── scope.md                    # 定位、范围、明确不做、已定约束
├── testing.md                      # 测了什么、故意不测什么、新测试放哪
├── todo/                           # 未决事项唯一入口（不许在别处开待办清单）
│   ├── README.md                   # 命名规则 + 索引表 + 「已定，不用再想」表
│   └── YYYY-MM-DD-TODO-*.md        # 按主题拆文件，日期是创建日
└── worklog/                        # 会话工作台：一次会话一份，只对创建它的那次会话有意义
    ├── README.md                   # 常驻说明；兼作「目录不消失」的占位
    └── YYYY-MM-DD-HHmm-*.md        # 按会话生成，随时可删
```

## 怎么读

- 缩进表示目录层级；`#` 后面是这一条**只做一件事**的说明。
- 带 `*` / `~` 的条目表示「同类文件若干」，不逐个列——`adr/` 只追加、`todo/` 按主题增删、`worklog/` 按会话生成且随时可删，列全了反而天天要改。
- **`adr/` 与 `decisions/` 不是一回事**：`adr/` 记**结论**（为什么这么定），`decisions/` 记**过程**（当时考虑过什么）。这是本项目最容易被外行混淆的一处，区分纪律见 [README.md](./README.md#adr-与-decisions-的区别)。
- 仓库根还有与文档相关的 [README.md](../README.md) / [CONTEXT.md](../CONTEXT.md) / [CHANGELOG.md](../CHANGELOG.md) / [AGENTS.md](../AGENTS.md) / [LICENSE](../LICENSE)、[.codebuddy/rules/](../.codebuddy/rules/) 与 [scripts/](../scripts/)——它们也进文档地图，但不属于 `docs/` 子树，故不画进树。

## 维护

- 只有 `docs/` 结构增删（新增顶层文档、新增主题目录）时才需要回来改这棵树。
- 被画进树的路径都写成链接，一旦文件被移走，`scripts/check-doc-links.sh` 会在提交前当场报红。
- 这张图与[文档地图](./README.md#文档地图)是同一批文件的两个视角：**树看形状，表看用途与真相源**，改结构时两处一起改。
- 想补齐某个目录属于未决事项 → 记到 [`docs/todo/`](./todo/)，不在这里排队。
