# 文档目录结构

> 这是 quizzy 的**现状图示**：只画层级与各文件职责，一句话一条。
> 谁有内容、谁对谁是真相源，以[文档地图](./README.md#文档地图)为准——那张表才是权威索引，这里只是把同一批文件画成树。
> 与文件系统或 [README.md](./README.md) 不一致时以它们为准，并顺手把本文件改回。

分成两棵树看：**先看仓库根（文档散在哪），再看 `docs/` 子树（文档体系内部长什么样）**。两者是同一批文件的两个视角，不重复列。

## 一、仓库根：文档都在哪

以 `quizzy/` 为根，只画**与文档相关**的东西——代码目录（`quizzy-server` / `quizzy-web` / `quizzy-mobile` / `question-bank` 等）只标出位置，内部结构与本文无关。

```

├── PRODUCT.md                      # 产品真相：受众 / 用途 / 定位 / 语气 / 约束
```

## 怎么读

- 缩进表示目录层级；`#` 后面是这一条**只做一件事**的说明。
- **第一棵树画「文档散在哪」**（含根目录文件与各子工程的 README），**第二棵树画 `docs/` 体系内部**；两棵树互不重复——`docs/` 在第一棵里只作为**一个节点**出现。
- 带 `*` / `~` 的条目表示「同类文件若干」，不逐个列——`adr/` 只追加、`todo/` 按主题增删、`worklog/` 按会话生成且随时可删，列全了反而天天要改。
- **决策只有 `adr/` 记**：结论与**被否的选项**都在同一张卡里（后者写在 Considered Options 一节）；过程记录归 `worklog/`，但它是过程、不是事实源。原 `decisions/` 那一类已于 2026-10-06 取消，见 [README.md](./README.md#决策只有-adr-记)。
- 两棵树里画到的文档都进[文档地图](./README.md#文档地图)，**用途与真相源一律以那张表为准**，本文不复述。

## 维护

- 改动**两处**任一即需回来改树：① 根目录或子工程的文档增删（第一棵）；② `docs/` 结构增删（第二棵）。改完记得同步[文档地图](./README.md#文档地图)。
- 被画进树的路径都写成**行内代码**（不是链接），因为不少路径在树里是示意（如 `NNNN-*.md`）；真要跳到文档，走文档地图的链接。若确实要写链接，`scripts/check-doc-links.sh` 会在提交前验它没断。
- 这两张图与[文档地图](./README.md#文档地图)是同一批文件的三个视角：**树看形状，表看用途与真相源**，改结构时一起改。
- 想补齐某个目录属于未决事项 → 记到 [`docs/todo/`](./todo/)，不在这里排队。
