# 前端（PC 端）

> **本文只讲 PC 端**（`quizzy-web`，Vue3 + Element Plus）。移动端 H5 与微信小程序是另一个工程，设计与边界见 [《移动端》](./移动端.md)。

**目的**：讲清 **PC 端**（`quizzy-web`，Vue3 + Element Plus）页面的组织方式、状态与服务端数据怎么流转，以及哪些边界容易踩。

**读者**：要改前端的人。

**真相源**：**路由、页面清单、组件清单以代码为准**（`quizzy-web/src/` 下的 `router/`、`views/`、`components/`、`stores/`、`api/`）。本文档只讲边界与约定，不复制那些清单。

---

## 页面流与信息架构

一条主线：登录 → 挑题（题库 / 组卷） → 答题 → 看结果 → 回头练错题。

- **题库**：题目的列表与维护入口，也是导入导出的入口
- **试卷**：固定卷与规则卷统一管理，规则卷可以在出卷时预览抽题
- **答题**：一次会话的作答界面，逐题推进，即时反馈
- **结果**：会话结算后的逐题回顾
- **历史**：会话列表，未完成的可以继续作答
- **错题本**：错题列表与一键错题重练
- **收藏夹**（`/favorites`）：左边是夹（第一个是「全部收藏」）、右边是这个夹里的题；能新建 / 改名 / 删夹、
  把某道题移出某个夹、用当前这个桶开一次练习
- **账户**（`/profile`）：一条**主线之外**的支线——账户自助，分「资料」（头像、昵称）与「安全」（改密码、退出所有设备、注销账号）两块

题库与试卷的编辑在抽屉里完成，不占独立路由。

## 路由与访问控制

路由定义见 `router/index.ts`。除登录注册外的路由需要登录态，由**路由守卫**统一拦截，token 存在 Store 里并做了持久化。

注意：路由守卫只挡「没登录」，**不挡「没有数据权限」**——后者由服务端判定（见 [《API》](API.md) 的数据边界一节）。

## 页面与组件边界

- 页面组件按上面的路由划分，放在 `views/`
- 「关于」是顶栏用户区的按钮 + 弹窗（`views/AboutDialog.vue`），**不做成独立路由**——它是低频元信息，不该占导航位
- **「账户」相反，它做成独立路由 `/profile`**：注销是不可逆操作，值得一个能停下来认真读、能收藏、能直接发给别人的地址；塞进弹窗容易顺手点错。入口同样在顶栏用户区。取舍见 [ADR 0027](../adr/0027-token-version-invalidates-all-devices.md)
- **顶栏用户区**：把原来的「昵称 + 退出」换成「头像 + 昵称」的下拉，里面放「我的账户」与「退出登录」；「外观」与「关于」保持原样平铺（不动上一版刚加的外观切换器）
- **头像展示没有值时用前端生成的默认方块头像**（按用户 id 派生），不是占位图或空白。见 [ADR 0028](../adr/0028-avatar-stored-in-database.md)
- **头像上传是本工程唯一的图片处理**：选图后用 canvas 压到最长边 ≤256px 再转 webp，以 data URL 提交；后端只收这份编码后的字符串，没有文件上传通道
- **收藏星标是一个可复用组件**（`components/FavoriteStar.vue`），题库列表 / 题目详情 / 答题结果 / 收藏夹页面都用它。
  ⚠️ 它是**短按收藏、长按（约 500ms）改收藏夹**——长按在桌面浏览器里几乎没有可发现性，所以横幅上的
  「修改收藏夹」按钮才是明路，长按只当快捷键；**改它的时候别把横幅去掉**。理由见 [ADR 0030](../adr/0030-favorites-as-named-folders.md)
- ⚠️ **「修改收藏夹」面板在两种模式下行为不同、名字也不同**（`components/FavoriteFoldersDialog.vue`）：
  单题叫「修改收藏夹」，是**覆盖**语义（勾谁就属于谁；**空选 = 留在默认夹**，不是取消收藏）；
  题库页批量叫「加入收藏夹」，是**只加不减**。别把批量也做成覆盖——那一次点击会静默改掉几十道题的归属。
  ⚠️ 面板**不预勾**当前归属，但**必须显示一行只读的「现在在：X」**——不预勾是为了让勾选出于主动表态，
  不是为了对现状闭口不谈；一道已收藏的题打开面板看到一片空白，那是在说谎（[ADR 0030](../adr/0030-favorites-as-named-folders.md)）。
  ⚠️ **别把它的加载挂到 `el-dialog` 的 `@open` 上**：星标用 `v-if` 懒挂载面板，首次打开时
  `modelValue` 一上来就是 `true`，而 element-plus 只在它**变化**时才 emit `open`
  ——首次打开会永远不加载、谎报「还没有收藏夹」。加载时机绑在组件自己的 `visible` 上。
- 题库页的**收藏夹筛选**把「全部收藏」做成下拉里的**可勾选项**（与「分类」把「全部分类」做成顶部动作不同）：
  后端那两个收藏条件之间是**包含关系**、不存在互斥，界面不需要发明谁赢的规则。
- 收藏夹页面与题库页**共用同一份题目组装**，但**不是同一个列表接口**：右列走
  `GET /api/favorites/questions`（**最近收藏的排最前**，跨夹去重），题库页走 `GET /api/questions`
  （**题目 id 倒序**）。⚠️ 所以右列的时间列是「这个桶里的收藏时间」，题库页的收藏筛选根本没有它。
  星标变了之后收藏夹页面要**整页重取**（那一行很可能已不属于当前结果集），而题库页只需就地改这一行的 `favorited`。
  ⚠️ **别给这张表加 `el-table` 的 `sortable`**：那只会排当前这一页，与服务端排序打架。
- ⚠️ **写在表格 / 滚动容器里面的弹窗必须加 `append-to-body`**（`components/FavoriteFoldersDialog.vue` 就是这么写的）：
  它在题库页挂在**表格单元格里的星标**上，不挂到 body 的话，遮罩与弹窗会被困在表格内部那一层
  （`el-table` 里的 `el-scrollbar`）——结果是**表格的行盖到弹窗上来**，主人的原话是
  「题库的文字被渲染到了收藏夹的面板」（2026-10-07）。端到端有 `expectDialogOnTop` 盯着它
  （`e2e/specs/support/helpers.ts`，命中测试 + 「遮罩不许落在表格里」两条判据）。
  页面级（`.el-main` 内、不在表格里）的弹窗没有这个问题，不必跟着加。
- 可复用组件放在 `components/`，其中 Markdown 渲染是重点：题干、选项、解析都是 Markdown，渲染器负责代码块高亮
- 类型定义集中在 `types/`，应与后端 VO 对应；**它不是独立契约源**，后端结构变化时以 springdoc 输出为准
- **试卷编辑抽屉的选题器跨页勾选「自己记账」**：用显式 checkbox + 一个 id 集合，不用 `el-table` 的 `selection`。
  它的选中态在换页时会被重置，靠 `reserve-selection` 才留得住，而「`selection-change` 到底带不带那些保留行」
  不够直观——一旦不带，用户在第二页点确认就会**静默丢掉第一页的选择**。自己记账则翻页前后行为完全确定。
- 抽屉里可以**内联新建题目**（复用 `QuestionEditDialog.vue`）：子组件保存后把新题 id 跟着 `saved` 事件回传，
  父组件直接加进卷，省掉「先去题库建、再回来选」那一趟。
- **题库页的批量选择用同一套做法**（自己记账，理由同上）：所以「已选 N 道」是**跨页**的，
  批量条必须把数量显式写出来——不写，翻到第二页就会以为第一页白勾了。
  批量动作只有两个：**加入已有试卷**（并入、已在卷中的自动忽略，只列固定卷）与**用所选新建试卷**。
- 导入弹窗里的「同时建一张试卷」**默认不勾**，不勾就还是老行为（只导入题目）；
  勾上后标题必填——后端把「有没有给卷名」直接当作建不建卷的开关（[《导入导出》](./导入导出.md)）。

## 状态与 API 访问

- Store 放全局状态：用户信息与 token（持久化）、当前会话状态。定义在 `stores/`
- **列表页的「筛选状态」放网址（`route.query`），不放 Store**：Store 一刷新就没了，而网址能
  让刷新与浏览器的前进后退都原样恢复条件。✅ 目前只有题库页这么做，向其他列表页铺开是未决事项，
  见 `docs/todo/`。用 `replace` 而不是 `push` 写网址，否则每改一次条件就多一条历史记录、
  按「后退」变成退回上一个下拉选项。
- ⚠️ **数组参数不能直接交给 axios**：它会把 `[1, 2]` 序列化成 `tagIds[]=1&tagIds[]=2`，
  而那个参数名后端不认识——筛选条件会**静默失效**（不报错、不提示，看起来就像「筛了跟没筛一样」）。
  必须手工摊成重复的参数名，见 `quizzy-web/src/api/question.ts` 里那个把条件转成参数的方法。
- HTTP 封装在 `api/request.ts`，统一处理 baseURL、token 注入、错误提示与响应解包
- 各领域的请求按模块拆分到 `api/` 下对应文件，不散落在组件里

## 界面主题（浅色 / 深色）

三档外观：**跟随系统 / 浅色 / 深色**，默认跟随系统。切换入口在**顶栏用户区**（「外观：<当前档>」）；
登录页没有顶栏，只能跟随已存的偏好。状态与持久化逻辑在 `stores/theme.ts`。

**机制**（改前端样式前先看这三条）：

- **开关就是 `<html>` 上的 `dark` 类**。这只是 Element Plus 的约定：`main.ts` 引入的
  `element-plus/theme-chalk/dark/css-vars.css` 里所有选择器都写成 `html.dark`，加上这个类即整体变暗。
  组件级颜色（含 `el-menu` 这类）都由 `--el-*` 变量驱动，所以**不用逐个组件覆盖**。
- **自有样式不许写死色值**，一律走 `var(--el-*)` 语义变量（如 `--el-bg-color`、`--el-text-color-secondary`、
  `--el-border-color-lighter`、`--el-color-success-light-9`）。可用的变量名以 Element Plus 的
  `theme-chalk/index.css` 与 `dark/css-vars.css` 为准，**本文不复制清单**（[ADR 0006](../adr/0006-bare-array-import-contract.md)）。
- **代码高亮的深色配色是唯一的例外**：`highlight.js` 的 `github.css` 与它自己的暗色版选择器**完全同名**，
  两份同时引入会互相覆盖，所以 `components/MarkdownRenderer.vue` 里手写了一份只在 `html.dark` 下生效的覆盖。

⚠️ 主题偏好的 `localStorage` key 在**两处**写着：`stores/theme.ts` 与 `index.html`。后者是首屏防闪烁的
内联脚本，必须在样式生效前同步执行、拿不到模块——改一处就必须一起改另一处，否则刷新会闪一下浅色。

## 组件库的语言与文案

Element Plus 的**内置文案默认是英文**（分页的 `Total 34` / `10/page`、`el-empty` 的 `No Data` 之类）。
`main.ts` 里 `app.use(ElementPlus, { locale: zhCn })` 把它整体换成中文——满屏中文里只飘着几句洋文，
是最容易被忽略的那类不一致。它只影响**组件内置**文案，自己写的按钮/提示/表头不受影响。

## 构建与类型检查

前端**只有类型检查与构建两个门禁**，没有单测也没有 lint（`package.json` 里没有这两个 script）。

⚠️ `vite build` 走 esbuild 只剥离类型、不做检查，所以**类型错误只会被 `typecheck` 挡住，构建永远是绿的**。别以为构建过了就是好的。详见 [../testing/README.md](../testing/README.md)。

## 构建期注入的版本与构建信息

`__APP_VERSION__` / `__APP_AHEAD__` / `__APP_COMMIT__` / `__APP_BUILD_TIME__` 四个全局常量由
`vite.config.ts` 的 `define` 生成，值来自 `docker build` 的 `--build-arg`；源头是 `git tag`，
算法与取舍见 [ADR 0015](../adr/0015-version-number-governance.md)。类型声明在 `src/env.d.ts`。

⚠️ **不能直接在模板里用这四个常量**：`<script setup>` 的模板只认 setup 作用域内的绑定，
未识别的标识符会被编译成 `_ctx.xxx` 从而拿到 `undefined`（不报错，只是不显示）。要先用普通
常量接一层，`AboutDialog.vue` 就是这么写的。

宿主机直跑（`npm run dev` / 本地 `npm run build`）时它们退化成 `dev` / `0` / `unknown` / `unknown`，
这是刻意的显式退化——留空在界面上看不出来。
