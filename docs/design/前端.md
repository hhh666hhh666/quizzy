# 前端（PC 端）

> **本文只讲 PC 端**（`quizzy-web`，Vue 3 + Vite + TypeScript + Pinia，组件基座 **reka-ui + shadcn-vue（源码入库）+ Tailwind CSS v4**）。移动端 H5 与微信小程序是另一个工程（uni-app），设计与边界见 [《移动端》](./移动端.md)。

**目的**：讲清 PC 端页面的组织方式、状态与服务端数据怎么流转，以及哪些边界容易踩。

**读者**：要改前端的人。

**真相源**：**路由、页面清单、组件清单以代码为准**（`quizzy-web/src/` 下的 `router/`、`views/`、`components/`、`stores/`、`api/`）。本文档只讲边界与约定，不复制那些清单（[ADR 0006](../adr/0006-bare-array-import-contract.md)）。

> ✅ **PC 端重建已于 2026-10-08 收官**（[ADR 0031](../adr/0031-pc-frontend-rebuild-shadcn-vue.md)）：Element Plus 已彻底退场，
> 全站为 reka-ui + 自建组件；视觉系统的**权威快照是仓根 [`DESIGN.md`](../../DESIGN.md)**，
> token 的**唯一真相源是 `quizzy-web/src/styles/tokens.css`**——改颜色 / 间距 / 圆角只改它，组件不许写死值。

## 页面流与信息架构

一条主线：登录 → 挑题（题库 / 组卷） → 答题 → 看结果 → 回头练错题。

- **题库**：题目的列表与维护入口，也是导入导出的入口
- **试卷**：固定卷与规则卷统一管理，规则卷可以在出卷时预览抽题
- **答题**：一次会话的作答界面，逐题推进，即时反馈
- **结果**：会话结算后的逐题回顾
- **历史**：会话列表，未完成的可以继续作答
- **错题本**：错题列表与一键错题重练
- **收藏夹**（`/favorites`）：左边是夹（第一个是「全部收藏」）、右边是这个夹里的题；能新建 / 改名 / 删夹、
  把某道题移出某个夹、用当前这个桶开一次练习
- **账户**（`/profile`）：一条**主线之外**的支线——账户自助，分「资料」（头像、昵称）与「安全」（改密码、
  退出登录、退出所有设备、注销账号）几块

题目的新建 / 编辑与试卷的编辑都用**弹窗**（reka Dialog）完成，不占独立路由。

## 路由与访问控制

路由定义见 `router/index.ts`。除登录注册外的路由需要登录态，由**路由守卫**统一拦截，token 存在 Store 里并做了持久化。
路由 `meta.title` 同时喂两处：顶栏那行标题与浏览器标签页标题（`document.title`，在 `afterEach` 里同步）。

注意：路由守卫只挡「没登录」，**不挡「没有数据权限」**——后者由服务端判定（见 [《API》](API.md) 的数据边界一节）。

## 页面与组件边界

- 页面组件按上面的路由划分，放在 `views/`
- **组件基座**：`components/ui/` 是 shadcn-vue 的**源码入库**（按需 `npx shadcn-vue add` 拉取后即归属本仓库，可改）；
  业务件放 `components/`。引入新组件库前先查它的**内置文案语言**——满屏中文里飘几句洋文是最容易被忽略的不一致
- **提示与确认是自建件**（Element Plus 退场后不引第二个 UI 库）：
  - `lib/toast.ts` + `components/Toaster.vue`：右下角轻提示，支持**一个动作按钮**（收藏横幅的「修改收藏夹」、
    取消收藏的「撤销」都在它上面）。类名 `.toast--success` 等是 **e2e 钩子**
  - `lib/box.ts` + `components/MessageBoxHost.vue`：确认框 / 输入框。⚠️ **取消走返回值**（`false` / `null`），
    **不靠 reject**——老写法每个调用点都要在 `catch` 里区分「取消」与「真失败」，别再抄回去
- **「关于」是弹窗、不是路由**——它是低频元信息，不该占导航位；入口在**侧栏底部的用户区**（与「外观」同排）
- **「账户」相反，是独立路由 `/profile`**：注销是不可逆操作，值得一个能停下来认真读、能收藏、能直接发给别人的地址；
  塞进弹窗容易顺手点错。入口同样在侧栏底部用户区；**「退出登录」在账户页安全卡**（仅退本设备）。
  「注销不可逆」依据见 [ADR 0029](../adr/0029-account-deletion-hard-delete.md)；范围见 [ADR 0019](../adr/0019-mobile-clients-with-uniapp.md) 补充段
- **用户区在侧栏底部**：圆框头像 + 昵称（点击都进账户页）+「当前外观档位 / 关于」单行；**不给整块加悬停底**
- **头像展示没有值时用前端生成的默认方块头像**（按用户 id 派生），圆形裁剪。见 [ADR 0028](../adr/0028-avatar-stored-in-database.md)
- **头像上传是本工程唯一的图片处理**：选图后 canvas 压到最长边 ≤256px 转 webp，以 data URL 提交；无文件上传通道
- **收藏星标是一个可复用组件**（`components/FavoriteStar.vue`），题库列表 / 题目详情 / 答题结果 / 收藏夹页面都用它。
  ⚠️ 它是**短按收藏、长按（约 500ms）改收藏夹**——长按在桌面端几乎没有可发现性，所以横幅上的「修改收藏夹」
  按钮才是明路，长按只当快捷键；**改它的时候别把横幅去掉**（[ADR 0030](../adr/0030-favorites-as-named-folders.md)）
- ⚠️ **「修改收藏夹」面板两种模式、名字不同**（`components/FavoriteFoldersDialog.vue`）：
  单题叫「修改收藏夹」，是**覆盖**语义（勾谁就属于谁；**空选 = 留在默认夹**，不是取消收藏）；
  题库页批量叫「加入收藏夹」，是**只加不减**。别把批量也做成覆盖——那一次点击会静默改掉几十道题的归属。
  ⚠️ 面板**不预勾**当前归属，但**必须显示一行只读的「现在在：X」**——不预勾是让勾选出于主动表态，
  不是为了对现状闭口不谈（[ADR 0030](../adr/0030-favorites-as-named-folders.md)）。
  ⚠️ **加载时机绑在组件自己的 `visible` 上**：星标用 `v-if` 懒挂载面板，「首次打开必须真的加载」有端到端哨兵盯着
  （历史上挂在第三方弹窗的 `@open` 上翻过车——那类事件在「挂载时就已经是打开态」时不触发）
- 题库页的**收藏夹筛选**把「全部收藏」做成下拉里的**可勾选项**（与「分类」把「全部分类」做成顶部动作不同）：
  后端那两个收藏条件之间是**包含关系**、不存在互斥，界面不需要发明谁赢的规则
- 收藏夹页面与题库页**共用同一份题目组装**，但**不是同一个列表接口**：右列走
  `GET /api/favorites/questions`（**最近收藏的排最前**，跨夹去重），题库页走 `GET /api/questions`
  （**题目 id 倒序**）。⚠️ 右列的时间列是「这个桶里的收藏时间」，题库页的收藏筛选根本没有它。
  星标变了之后收藏夹页面要**整页重取**（那一行很可能已不属于当前结果集），而题库页只需就地改这一行的 `favorited`。
  ⚠️ **排序是服务端的事**：别给列表加客户端排序——那只会排当前这一页，与服务端顺序打架
- ⚠️ **「分类」与「标签」是可创建下拉**（`components/CreatableSelect.vue`，单/多选共用）：
  输入新名字回车即建（新分类的名字以字符串进 `categoryName` 交给后端按名解析，id 位置留空）。
  它的面板类名 `.create-select-panel` 是 **e2e 钩子**；Esc 只在面板开着时拦截（别把外层弹窗一起关掉）
- **可点元素一律是真按钮**：行内动作（查看 / 编辑 / 移除）用 `.link-button` 统一件（hover 下划线 + 键盘焦点环），
  别用 `div` 加 `@click`——键盘用户会丢焦点指示（规范审查整改过一轮）
- **弹窗一律走 reka Dialog（portal 到 body）**：历史上「表格里的弹窗要被表格行穿透」的坑在结构上消失；
  端到端仍有 `expectDialogOnTop` 盯着层级（`e2e/specs/support/helpers.ts`，命中测试 + 根因两条判据）
- 可复用组件放在 `components/`，其中 Markdown 渲染是重点：题干、选项、解析都是 Markdown，渲染器负责代码块高亮
- 类型定义集中在 `types/`，应与后端 VO 对应；**它不是独立契约源**，后端结构变化时以 springdoc 输出为准。
  ⚠️ 它与 `quizzy-mobile/src/types/index.ts` **逐字同步**（CI 有 `diff -u` 守卫）
- **试卷编辑弹窗的选题器跨页勾选「自己记账」**：用显式 checkbox + 一个 id 集合，不用任何表格组件的 selection。
  组件内建的选中态换页会重置，靠 `reserve-selection` 才留得住，而它的 change 事件带不带保留行不够直观——
  一旦不带，用户在第二页点确认就会**静默丢掉第一页的选择**。自己记账则翻页前后行为完全确定
- 弹窗里可以**内联新建题目**（复用 `QuestionEditDialog.vue`）：子组件保存后把新题 id 跟着 `saved` 事件回传，
  父组件直接加进卷，省掉「先去题库建、再回来选」那一趟
- **题库页的批量选择用同一套做法**（自己记账，理由同上）：「已选 N 道」是**跨页**的，批量条必须把数量显式写出来。
  批量动作只有两个：**加入已有试卷**（并入、已在卷中的自动忽略，只列固定卷）与**用所选新建试卷**
- 导入弹窗里的「同时建一张试卷」**默认不勾**；勾上后标题必填——后端把「有没有给卷名」直接当作建不建卷的开关
  （[《导入导出》](./导入导出.md)）

## 状态与 API 访问

- Store 放全局状态：用户信息与 token（持久化）、外观档位。定义在 `stores/`
- **列表页的「筛选状态」放网址（`route.query`），不放 Store**：Store 一刷新就没了，而网址能让刷新与浏览器的
  前进后退都原样恢复条件。**现状：题库 / 答题记录 / 试卷 / 错题本四个列表页已铺开**（筛选 + 分页）。
  约定三条：**脏值忽略**（手改网址塞非法枚举要退回默认，别让后端 400）、**默认值不写进网址**
  （什么都没筛就是干净的 `/xxx`）、**用 `replace` 而不是 `push`**（否则每改一次条件就多一条历史记录、
  按「后退」变成退回上一个下拉选项）
- ⚠️ **数组参数不能直接交给 axios**：它会把 `[1, 2]` 序列化成 `tagIds[]=1&tagIds[]=2`，
  而那个参数名后端不认识——筛选条件会**静默失效**（不报错、不提示，看起来就像「筛了跟没筛一样」）。
  必须手工摊成重复的参数名，见 `quizzy-web/src/api/question.ts` 里那个把条件转成参数的方法
- HTTP 封装在 `api/request.ts`，统一处理 baseURL、token 注入、错误提示（走自建 toast）与响应解包
- 各领域的请求按模块拆分到 `api/` 下对应文件，不散落在组件里

## 界面主题（浅色 / 深色）

三档外观：**跟随系统 / 浅色 / 深色**，默认跟随系统。切换入口在**侧栏底部用户区**（显示当前档位）；
登录页没有侧栏，只能跟随已存的偏好。状态与持久化逻辑在 `stores/theme.ts`。

**机制**（改前端样式前先看这几条）：

- **开关就是 `<html>` 上的 `dark` 类**，颜色全部由 `tokens.css` 驱动——**不用逐个组件覆盖**。
  ⚠️ **深色色板尚未落地**：当前 `dark` 档只切 `color-scheme` 与少数组件内联的深色变体，
  完整色板属后续功能（见 `docs/requirements/功能展望.md`）
- **自有样式不许写死色值**，一律走 token（如 `bg-surface`、`text-ink-muted`、`var(--color-brand)`）。
  可用变量名以 `tokens.css` 为准，**本文不复制清单**（[ADR 0006](../adr/0006-bare-array-import-contract.md)）
- 浏览器 UI 的配色（`meta[name=theme-color]`）跟着 `apply()` 更新；**代码高亮的深色配色是唯一的例外**：
  highlight.js 两份主题选择器同名，`components/MarkdownRenderer.vue` 里手写了一份只在 `html.dark` 下生效的覆盖

⚠️ 主题偏好的 `localStorage` key 在**两处**写着：`stores/theme.ts` 与 `index.html`。后者是首屏防闪烁的
内联脚本，必须在样式生效前同步执行、拿不到模块——改一处就必须一起改另一处，否则刷新会闪一下浅色。

## 构建与类型检查

前端**只有类型检查与构建两个门禁**，没有单测也没有 lint（`package.json` 里没有这两个 script；
「要不要补组件测试」的结论与理由见 [《测试系统说明》](../testing/系统说明.md)）。

⚠️ `vite build` 走 esbuild 只剥离类型、不做检查，所以**类型错误只会被 `typecheck` 挡住，构建永远是绿的**。别以为构建过了就是好的。详见 [../testing/README.md](../testing/README.md)。

## 构建期注入的版本与构建信息

`__APP_VERSION__` / `__APP_AHEAD__` / `__APP_COMMIT__` / `__APP_BUILD_TIME__` 四个全局常量由
`vite.config.ts` 的 `define` 生成，值来自 `docker build` 的 `--build-arg`；源头是 `git tag`，
算法与取舍见 [ADR 0015](../adr/0015-version-number-governance.md)。类型声明在 `src/env.d.ts`。

⚠️ **不能直接在模板里用这四个常量**：`<script setup>` 的模板只认 setup 作用域内的绑定，
未识别的标识符会被编译成 `_ctx.xxx` 从而拿到 `undefined`（不报错，只是不显示）。要先用普通
常量接一层，`AboutDialog.vue` 就是这么写的。

宿主机直跑（`npm run dev` / 本地 `npm run build`）时它们退化成 `dev` / `0` / `unknown` / `unknown`，
这是刻意的显式退化——留空在界面上看不出来。

### 材质语言（已落地）

| 层 | 管什么 | 用什么 |
|---|---|---|
| **铺底 = 面** | 页面底 / 卡片 / 表格 / 表单（99% 的界面） | `canvas` / `surface` / `surface-2` / `tint-*`。**不许用玻璃** |
| **浮层 = 练习纸实底** | 弹窗 / 下拉 / 提示 | 近白 `reader` 面 + 1px 描边 + 遮罩压暗。**有意不用模糊玻璃**（弹窗里表单与正文占大头，实底保对比度） |
| 顶栏 | 夹在两者之间 | `.glass-bar`（半透明但**不模糊**；主内容从它下面穿过） |
| 侧栏 | 夹在两者之间 | **实心有色面**（`bg-surface-2`）——它后面没有内容可透，不用玻璃 |

⚠️ **三条硬规矩**：① 同一类元素**只用一种语言**（浮层全实底、铺底全面），否则像两个人做的；
② 玻璃**背后必须有内容可透**，浮在纯白上等于白付性能；③ **玻璃上不许放长正文**——正文永远在
`--color-reader`（近白）上。

具体数值与理由见 `quizzy-web/src/styles/tokens.css` 的注释与根 `DESIGN.md`（**单一信息源，本文件不复述数值**）。

### 挑定的构图（已落地）

2026-10-08 挑版定的页面形态（**只记结论**——参照图属一次性参照，不进仓库、不在此复述）：

- **登录页 = 双栏构图**：左边一整块身份面（tint 容器，放 wordmark 与副文案），右边近白面放表单。
- 登录与注册**同卡两态**：「还没有账号？注册」是链接，点击切到注册表单，**不新增路由**。
- 其余页面沿用现行信息架构（依据：ADR 0031「本轮不动信息架构」）。
