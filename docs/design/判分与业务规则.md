# 判分与业务规则

**目的**：讲清「怎么算对、怎么算分、错题怎么出来、规则卷怎么抽题」这些不能用字段推断出来的业务语义。

**读者**：要改判分、会话、错题本、组卷逻辑的人。

**真相源**：规则本身写在本文档；具体算法实现以 `ScoreStrategy`、`QuizService`、`PaperService`、`WrongBookService` 为准，阈值常量也看代码。

---

## 判分规则

| 题型 | 怎么算对 |
|------|----------|
| 单选 | 选中项与正确答案一致 |
| 判断 | 同单选（选项固定为「正确 / 错误」两项） |
| 多选 | 选中集合与正确答案集合**完全一致**（顺序无关），少选、多选、错选都不得分 |

每题分值由出题人指定，**没有部分分、没有倒扣分**。

为什么多选要求全对：这里是练习语义，目的把不确定的题筛出来反复练；给部分分会让「半懂」伪装成「懂了」。理由见 [ADR 0004](../adr/0004-multi-choice-all-or-nothing.md)。

## 会话、即时反馈与结算

一次会话是一次完整的作答过程：发起时被分配一批题，之后逐题提交，最后结算。

- **即时反馈**：单题提交后立即返回「对不对、正确答案是什么、解析是什么、拿了几分」
- **可回退**：已答的题可以回去改答案
- **断点续答**：每题作答即时落库，刷新或重启都能接着做（不引 Redis，理由见 [ADR 0002](../adr/0002-answer-progress-in-mysql.md)）
- **结束方式**：正常结算或主动放弃，两者都记录为终态

**未作答的题**：不计分，也**不计入正确率的分母**；结算时提示还有几题没答。

**正确率** = 答对题数 ÷ **已作答**题数；**得分** = 各题实得分之和。具体计算见 `QuizService`。

## 错题本与掌握规则

错题本是从作答统计投影出来的状态（结构见 [《数据模型》](数据模型.md)），规则是：

- 答错 → 进入错题本，连续答对次数清零
- 答对 → 连续答对次数累加
- 连续答对达到阈值 → 自动移出错题本（视为已掌握）
- 手动移出 → 直接按已掌握处理

「连续答对几次算掌握」这个阈值的**具体数值以代码为准**，不在这里写死数字。

## 试卷与抽题规则

试卷有两种形态：

| 形态 | 存什么 | 什么时候抽题 |
|------|--------|--------------|
| **固定卷** | 明确的题目列表 | 出卷时就定死，每次作答都是同一批题 |
| **规则卷** | 抽题条件 | 每次作答时按条件现场抽，两次拿到的题可能不同 |

规则卷的条件包括：分类、标签、题型、难度、题量，以及是否避开最近做过的题。**条件的字段定义见 `PaperRuleDTO`**，执行逻辑见 `PaperService`。

规则卷支持**预览抽题**（不落库），方便确认抽出来的题合不合意。

快速练习（不建试卷直接抽一批题开一次会话）与错题重练（拿错题本里的题开一次会话）复用同一套规则结构。
