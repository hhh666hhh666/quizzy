# 数据模型

**目的**：讲清数据是怎么组织的、各对象之间什么关系，以及那些不写在字段注释里的语义（谁看得见什么、删掉意味着什么、错题本到底存不存在）。

**读者**：要改数据结构或写查询的人。

**真相源**：**表结构与字段一律以 Flyway 迁移脚本为准**（见下方「Schema 真相源」），本文档只讲语义。

---

## 实体关系概览

五个核心对象，围绕「一道题反复练」组织：

- **题目**：练习单元，带若干选项、正确答案与解析，归入一个分类、可挂多个标签
- **试卷**：一组题目的可复用组合，固定卷存题目列表，规则卷存抽题条件
- **会话**：用户某一次完整的作答过程，包含这次被分配的题目与每道题的作答结果
- **作答统计**：某个用户对某道题的累计表现（做过几次、连续答对几次）
- **收藏夹**：用户自己命名的一组题目，一道题可以同时在多个夹里；「收藏」= 在至少一个夹里
- **用户**：题目、试卷、会话的归属

题目与选项是主从关系；题目与标签是多对多；会话与题目通过「这次作答了哪几题」关联；收藏夹与题目也是多对多。

## 题目归属与可见性

题目只有两种归属：

- **公开题**（`owner_id` 为空）：所有登录用户都能看到，但**谁都不能改**
- **我的题目**（`owner_id` = 创建者）：只有本人能改

查询时的可见性规则是「未被软删 且（是公开题 或 是自己的题）」。用户自建的题目一律是「我的题目」，页面没有「设为公开」的入口——理由见 [ADR 0003](../adr/0003-public-questions-by-empty-owner.md)。

## 生命周期与逻辑删除

题目是**逻辑删除**，不是物理删除：删除只是置标记位，历史作答记录仍然引用它。

这带来一个必须知道的后果：**历史作答不做题目快照**。题目被修改后，历史会话里回顾到的内容（包括解析）会是**当前**的版本，而不是作答那一刻的版本。在小规模个人使用下这是可接受的取舍；真需要快照时，做法是在作答记录里冗余题干字段，而不是恢复物理删除。

⚠️ 另一个容易踩的点：删除题目时，**作答统计是物理删除**（题目本身只是软删）。所以「删掉再重新导入」会连带丢掉这道题的正确率数据与错题本标记——这不是 bug，但比看起来贵。批量动题库之前务必想清楚。

## 会话、作答统计与错题本

**错题本不是一张表，也没有对应的实体**——它是从作答统计投影出来的状态：某题答错过、且还没被判定为掌握，它就在错题本里。

- 答错 → 计入错题本，连续答对次数清零
- 答对 → 连续答对次数累加；达到阈值 → 自动移出错题本
- 手动移出 → 直接标记为已掌握

这条投影设计是有意为之：独立实体会引发「题目改了错题本里要不要跟着改」的同步问题。理由见 [《判分与业务规则》](../design/判分与业务规则.md)。

⚠️ **计数口径**：一次会话里同一道题只会被计一次——已作答的题不能再改答案（[ADR 0022](../adr/0022-answer-is-final.md)），所以同一道题**不会在同一个会话里**把 `answer_count` 累加两次、也不会出现「先答错点亮错题本、改成正确又把标记抹掉」这种自相矛盾的状态。

## 收藏夹

**收藏不是投影出来的**——错题本「不是一张表」是因为它完全由作答统计决定，而收藏是用户的主动选择。
所以它有两张真表：`favorite_folder`（夹）与 `favorite_folder_question`（夹 ↔ 题）。

- **「收藏」= 这道题在至少一个夹里**。不存在独立于收藏夹的收藏状态，因此**没有「未分组」**：
  取消收藏 = 从所有夹移出；删掉一个夹只把题从它里面移出，题若因此不属于任何夹，就不再是收藏。
- 每个用户天然有一个**默认收藏夹**（`is_default = 1`），点星标时题先落进它。它**按需创建**（存量账号
  不必做数据迁移）、**不可删除**、**可以改名**——所以它的名字不许写死进任何界面文案。
- 夹名在**同一用户内唯一**（与「昵称允许重名」不冲突：夹名是自己挑东西时的路标）。
- ⚠️ **夹列表的排序不存字段**：按该夹在 `favorite_folder_question` 里 `create_time` 的**最大值**
  （即「最近一次有新题进来」）倒序聚合出来，空夹排最后。存一列冗余的「最后使用时间」会在删题、
  改归属这些路径上漂掉。两张新表的时间列用 `DATETIME(3)`，因为排序就靠它，秒级精度会让同一秒内
  动过的两个夹并列。
- 收藏夹页面**右列的题也按这一列倒序**（「最近收藏的排最前」）。「全部收藏」是跨夹视角，
  同一道题在多个夹里**只出现一次**，时间取它在各夹 `create_time` 里的最大值。
- 删题时收藏关联跟着**硬删**（与「删题硬删作答统计」同一口径，不留指向已删题的悬挂行）。

理由与被否的替代方案见 [ADR 0030](../adr/0030-favorites-as-named-folders.md)。

## 用户与注销

用户是题目、试卷、会话的归属者（词义见 [`CONTEXT.md`](../../CONTEXT.md) 的「用户」）。注销是**硬删**：`user` 行连同他的题目、选项、标签关联、试卷、试卷题目、作答统计、会话、作答一起物理删除。

两件容易想错的事：

- **注销不走软删**。项目里只有题目用逻辑删除，这条路径刻意不用——他的会话与统计也一起删了，已经没有任何东西再引用那些题行，留着只会变成 `owner_id` 指向一个已不存在用户的悬挂行。理由见 [ADR 0029](../adr/0029-account-deletion-hard-delete.md)。
- **永远只影响他自己那一套**。用户无法把自己的私题转成公开题（[ADR 0003](../adr/0003-public-questions-by-empty-owner.md)），别人也无法把他的私题加进自己的卷——所以不存在「删了他，别人的东西挂掉」的情况。

⚠️ 库里**没有任何外键**，也就没有数据库级级联兜底：注销的清理必须在应用层逐表完成，并且放在一个事务里。
