# 数据模型

**目的**：讲清数据是怎么组织的、各对象之间什么关系，以及那些不写在字段注释里的语义（谁看得见什么、删掉意味着什么、错题本到底存不存在）。

**读者**：要改数据结构或写查询的人。

**真相源**：**表结构与字段一律以 Flyway 迁移脚本为准**（见下方「Schema 真相源」），本文档只讲语义。

---

## 实体关系概览

五个核心对象，围绕「一道题反复练」组织：

- **题目**：练习单元，带若干选项、正确答案与解析，归入一个分类、可挂多个标签
- **试卷**：一组题目的可复用组合，固定卷存题目列表，规则卷存抽题条件
- **会话**：用户某一次完整的作答过程，包含这次被分配的题目与每道题的作答结果
- **作答统计**：某个用户对某道题的累计表现（做过几次、连续答对几次）
- **用户**：题目、试卷、会话的归属

题目与选项是主从关系；题目与标签是多对多；会话与题目通过「这次作答了哪几题」关联。

## 题目归属与可见性

题目只有两种归属：

- **公开题**（`owner_id` 为空）：所有登录用户都能看到，但**谁都不能改**
- **我的题目**（`owner_id` = 创建者）：只有本人能改

查询时的可见性规则是「未被软删 且（是公开题 或 是自己的题）」。用户自建的题目一律是「我的题目」，页面没有「设为公开」的入口——理由见 [ADR 0003](../adr/0003-public-questions-by-empty-owner.md)。

## 生命周期与逻辑删除

题目是**逻辑删除**，不是物理删除：删除只是置标记位，历史作答记录仍然引用它。

这带来一个必须知道的后果：**历史作答不做题目快照**。题目被修改后，历史会话里回顾到的内容（包括解析）会是**当前**的版本，而不是作答那一刻的版本。在小规模个人使用下这是可接受的取舍；真需要快照时，做法是在作答记录里冗余题干字段，而不是恢复物理删除。

⚠️ 另一个容易踩的点：删除题目时，**作答统计是物理删除**（题目本身只是软删）。所以「删掉再重新导入」会连带丢掉这道题的正确率数据与错题本标记——这不是 bug，但比看起来贵。批量动题库之前务必想清楚。

## 会话、作答统计与错题本

**错题本不是一张表，也没有对应的实体**——它是从作答统计投影出来的状态：某题答错过、且还没被判定为掌握，它就在错题本里。

- 答错 → 计入错题本，连续答对次数清零
- 答对 → 连续答对次数累加；达到阈值 → 自动移出错题本
- 手动移出 → 直接标记为已掌握

这条投影设计是有意为之：独立实体会引发「题目改了错题本里要不要跟着改」的同步问题。理由见 [《判分与业务规则》](../design/判分与业务规则.md) 与 [`docs/decisions/records-and-glossary.md`](../decisions/records-and-glossary.md)。
