# 导入导出

**目的**：说清批量导入导出的**契约形状与容错语义**——尤其是那个曾经和实现漂移过一次的地方。

**读者**：要改导入导出功能、或要给题库生成工具对齐格式的人。

**真相源**：字段与校验规则以 `QuestionImportDTO`、`QuestionExcelRow`、`QuestionImportService` 为准；接口签名以 `QuestionImportExportController` 为准。

---

## 能力边界

- **两种格式**：Excel（主）与 JSON（辅），双向导入导出
- **导入是部分成功语义**：逐条校验，通过的入库，不通过的跳过，最后给出逐行错误报告（理由见 [ADR 0005](../adr/0005-import-skips-bad-rows.md)）
- **分类与标签**：导入时遇到不存在的会自动创建、同名复用。所以**标签必须收敛**，否则会污染全局标签库

⚠️ **导入不幂等**：同一份文件导入两次会建出两套重复题，实现上没有任何按题干查重。纪律是「一份文件只导一次」。

## Excel 模板

**优先从运行中的应用下载模板**（题库页的「下载导入模板」）——它一定和当前代码一致，文档里的描述会漂。

- 列定义的实现：`QuestionExcelRow`
- 模板生成逻辑：`QuestionImportService` 的模板写出方法

题型、难度等取值说的是英文值（如 `single` / `multi` / `judge`、`easy` / `medium` / `hard`），但也接受常见中文写法。题干、选项、解析都支持 Markdown。

## JSON 契约

**导入接口收的是题目对象的裸数组**，外层没有 `{"questions": [...]}` 这种包装。

这一条是有代价才换来的结论：`DESIGN.md` 当年把它写成了包装对象，与实际收发的不一致，最后以实现为准修正——全过程记在 [ADR 0006](../adr/0006-bare-array-import-contract.md) 里，包括「将来要加元信息时必须改回包装对象」这个后果。

**字段清单不在这里抄**，看 `QuestionImportDTO`（或从页面导出一份 JSON 作为样例）。要点只有几个：

- 顶层是数组，每个元素是一道完整的题
- 选项用 label 标识（A 起），答案用 label 列表表达，因此多选天然支持多个正确答案
- 判断题固定两个选项；分类与标签同样是「不存在则创建」

## 校验与错误处理

导入的校验是**逐条**的，失败只影响那一条：

- 返回结果是「总数 / 成功数 / 失败明细」，失败明细用题干标识是哪一行
- 前端用表格展示失败行，并提供错误报告下载

所以导入后的第一件事是**看错误报告**，而不是假设全成。

## 导出与兼容性

导出主要用于两件事：拿样例（导出一份 JSON 当作模板）、备份题库到文件后再回灌。导出范围支持按归属范围与指定题目筛选，实现见 `QuestionImportExportController`。

## 变更规则

**导入契约一旦改动，必须同步四处**，只改文档或只改 DTO 都会造成下一次漂移：

1. DTO 与 Service（`QuestionImportDTO` / `QuestionImportService`）
2. springdoc 生成的接口文档（随代码自动更新）
3. `md-to-question-bank` skill 里的契约描述（题库生成工具，**装在仓库外的全局技能目录**，它按裸数组产出）
4. 相关 ADR 的状态——如果结论变了，新增 ADR 而非改动旧的
