# 移动端（H5 与微信小程序）

**目的**：说清移动端的定位与边界——它做什么、不做什么，以及和 PC 端、和后端的关系。

**读者**：要改移动端的人；判断某个功能该不该进移动端的人。

**真相源**：**现阶段本文档是移动端设计的唯一真相源**——`quizzy-mobile/` 工程尚未建立，没有代码可指。
工程建立后，路由、页面清单、组件清单改为以 `quizzy-mobile/src/` 下代码为准，本文档只讲边界与约定（与 [《前端》](前端.md) 的演化路径一致）。

---

## 定位与范围

移动端是 PC 之外的**新客户端形态**，**只做「消费」**：

- 答题（逐题作答、即时判分、断点续答）
- 快速练习（按条件随机抽题）
- 错题本（列表、重练、手动移出）
- 答题记录（历史会话、继续未完成）
- **只读的试卷列表** + 从已有试卷开始答题（不做新建 / 编辑 / 删除）

「建设」类功能——题库增删改查、组卷、Excel / JSON 导入导出——**留在 PC**。
理由与取舍见 [ADR 0019](../adr/0019-mobile-clients-with-uniapp.md)；它只新增入口、不新增业务能力，见 [《需求范围》](../requirements/scope.md)。

## 与 PC 端的关系

- `quizzy-web`（PC，Vue3 + Element Plus）**完全不动**；移动端是**全新工程、全新移动设计**，不是把 PC 页面压窄。
- 两端**共用同一后端与同一账号**。
- 移动端与小程序共用同一份代码，差异用条件编译处理。

## 工程与编译目标

- 顶层目录 `quizzy-mobile`，与 `quizzy-server` / `quizzy-web` 并列；**暂不引入** monorepo 工具链。
- 基于 **uni-app（Vue3）**，一套代码编译两个目标：**H5** 与**微信小程序**。
- 交付顺序：**先跑通 H5**（登录 + 刷题闭环），小程序作为第二编译目标紧随。

## 页面流与信息架构

一条主线与 PC 同构，但页面按移动交互重新设计：

登录 → 挑题（只读试卷列表 / 快速练习） → 答题 → 结果 → 回头练错题 / 看记录。

具体页面清单在工程建立后以代码为准（见文首的真相源说明）。

## 与后端的边界

- 复用现有 `/api/**` 接口，**后端不改**。
- 从已有试卷答题走 `QuizStartDTO.sourceType = PAPER`（另有 `QUICK` / `WRONG_BOOK`）。
- 接口的**确切路径、字段与错误语义以 springdoc 为准**，见 [《API》](API.md)——本文档不复制接口清单。

## 登录与鉴权

- 复用 `POST /api/auth/login`（用户名密码），拿**无状态 Bearer JWT**，与 PC 同一套。
- 微信登录（`wx.login → code2session → 账号绑定`）**后置**，不在此展开，见 `docs/todo/`。

## 部署

- H5 走**同域子路径 `/m/`**（与 PC 同域名），因此**不需要新增 CORS**。
- **不做 PWA**（不引 manifest / Service Worker）；类 App 体验交给小程序。
- 小程序需要 HTTPS + 已备案域名 + 微信「request 合法域名」白名单——**备案是外部前置**。
