# 待办：镜像 tag 与分发

创建：2026-09-20 · 状态：已解决 · 优先级：低

## 2026-10-01 更新：registry 也定了，本条结案

prod 从本机搬到阿里云 ECS（[ADR 0016](../../adr/0016-cloud-deploy-with-release-pipeline.md)），触发条件
「出现第二台需要跑这套东西的机器」达成，剩下三个问题一次答完：

- **打到哪个 registry** → **已定：阿里云 ACR 个人版**，命名空间 `quizzy`。选它是因为 CI 在境外 GitHub runner、
  服务器在大陆，两端最优相反；ACR 让「拉取」这一端（更频繁、更贴近故障）变快变稳，代价只是 CI 那一端跨境推送。
  ⚠️ **个人版不支持 AccessKey 推送**，必须用「阿里云账号全名 + ACR 固定密码」，否则 CI 会一直 401。
- **构建放在 CI 还是本机手动推** → **已定：CI**，并进一步变成「推 tag 即自动部署」。
- **要不要加 `latest` 之类的浮动 tag** → **暂不加**。版本 tag 跟随 `git tag`（[ADR 0015](../../adr/0015-version-number-governance.md)）是回滚的唯一落点，
  浮动 tag 只会让「现在线上跑的是哪个版本」变得说不清。真要加，等出现「需要一个稳定别名」的消费者再说。

顺带回答了原方案里「回滚靠本地镜像」的隐患：ACR 保留每个版本，回滚不再依赖某台机器上恰好还留着镜像。

## 2026-10-01 更新：tag 那一半已定

做「关于」功能时顺带把版本号治理定了（[ADR 0015](../../adr/0015-version-number-governance.md)），
原先挂着的第三个问题因此有了答案：

- **tag 用固定版本号还是 git sha** → **已定：固定版本号，跟随 `git tag`**。
  由 `scripts/check-version.sh` 在打 tag 时校验包版本、`pom.xml` 与 compose 的镜像 tag 三处一致
  （CI 的「版本 · tag 与三处对齐」job）。选固定版本号而不是 sha，直接原因是 compose 的 `image:`
  必须是**字面量**——tag 里带 sha 就只能改成 `.env` 变量替换，而那与 [ADR 0011](../../adr/0011-env-file-with-local-defaults.md)
  对 `.env` 的定位（密钥与本机配置）冲突。附带好处：每个已发版本各留一份镜像，回滚可复用本地镜像。

**registry 分发仍暂缓**，触发条件不变：出现第二台需要跑这套东西的机器时再定。

## 2026-09-24 更新：三个问题里有一个半已经有了答案

CI 落地后（ADR 0013），原先挂着的三个问题进展不一：

- **构建放在 CI 还是本机手动推** → **已定：CI**。GitHub 托管 runner 上已经在稳定构建两个镜像，构建既不发生在开发机上，也不依赖本机网络。剩下的问题只剩「推到哪」。
- **打到哪个 registry** → 前半句要修正。原来写的「Docker Hub 在本机不通」是**本机**的限制（ADR 0010，且仅针对基础镜像的 `auth.docker.io`），CI 在境外 runner 上直连正常，所以 Docker Hub 重新成为候选。另外**可以**配 Docker Hub 账号 PAT（secrets `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN`）把拉取限额从「匿名 100 次/6 小时按 IP 计」提到「200 次/6 小时按账号计」——**目前尚未配置**，CI 的登录步骤会自动跳过，不影响运行。
- **tag 用固定版本号还是 git sha** → 仍未定，CI 目前不推镜像，tag 固定 `0.1.0`。

**状态保持「暂缓」**，触发条件不变：**出现第二台需要跑这套东西的机器**时，再连同 registry、tag、拉取凭据一起决定。

目前只在本地打 `quizzy-server` / `quizzy-web` 两个仓库的镜像（tag 跟随版本号，见上面的 10-01 更新），
没推任何 registry。

当前是纯本机自用，没有消费者，推了也没人拉，所以刻意暂缓。**什么时候需要第二台机器跑，什么时候再定。**

到时候要一起决定的：

- 打到哪个 registry（Docker Hub 在本机不通，基础镜像都得走 `docker.m.daocloud.io` 转 tag，见 ADR 0010）
- 构建放在 CI 还是本机手动推（推镜像这一步；构建本身已经在 CI 上了）
- 要不要给镜像加 `latest` 之类的浮动 tag
