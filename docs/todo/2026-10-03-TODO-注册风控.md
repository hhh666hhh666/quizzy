## 公开注册承诺的「图形验证码 + 按 IP 限流」代码里完全没有

[《需求范围》](../requirements/scope.md) 与 [ADR 0017](../adr/0017-public-signup-service.md) 都把「图形验证码 + 注册接口按 IP 限流 + 最小封禁开关」写成**公开注册的准入门槛**，但**后端代码里一个字都没实现**——全仓搜 `captcha` / `RateLimit` / `@WebFilter` 零命中。这是承诺与实现之间的缺口。

**现状**：站点已按公开服务运行（迁移进行中），注册接口目前是裸奔的。

**为什么现在定不下来**：真实用户量与垃圾注册的实际规模都还是零，现在按负载选型是空谈；但门槛本身是已承诺的，不该无限期拖。

**可选方案与倾向**：

- **验证码**：自绘图形 / 滑块 / 第三方，三选一。倾向先用最简单的**自绘图形验证码**，够挡住脚本注册即可。
- **限流维度与阈值**：按 IP 限注册频率，必要时叠加按用户名 / 邮箱。阈值待有真实流量后再调。

⚠️ 该项**优先于小程序上线**——多开一个公网入口会把滥用面再放大一层。

**做这件事时还要一起定的**：

- [ADR 0017](../adr/0017-public-signup-service.md) 提到的**最小账号封禁开关**是否也已实现（若不是，一并纳入）。
- 与 [`docs/todo/2026-10-01-TODO-邮箱验证.md`](./2026-10-01-TODO-邮箱验证.md) 的「发码限流维度」有交集，两处**不重复开清单**。
- 验证码 / 限流状态存哪——[ADR 0002](../adr/0002-answer-progress-in-mysql.md) 定了不引 Redis，所以落 MySQL 或进程内。
