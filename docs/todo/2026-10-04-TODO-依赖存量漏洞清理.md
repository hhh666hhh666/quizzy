## 发现了什么

CI 的 `deps` job（依赖安全扫描，见 `docs/decisions/ci-gate-setup.md` 的 D11 / D12）上线后，
顺带把仓库的 Dependabot alerts 打开了。当前 **39 条 open 告警，全部在 npm 侧**：

|--------|----|------|
| high | `adm-zip` | 5 |
| high | `vite` | 2 |
| high | `postcss` | 2 |
| high | `braces` | 1 |

| low | `vite` ×2、`send`、`qs`、`postcss-selector-parser`、`cookie`、`@babel/core` | — |

## ⚠️ 它们不会挡 CI——这是刻意的，别误以为「扫过了」

`deps` job 比的是 **PR 的增量**（base 与 head 两份快照的 diff）。
这 39 条是**存量**：base 与 head 上一样，进不了 diff，所以**永远不会让门禁变红**。

> ⇒ 这条门禁的语义是「**别再往里加新的**」，**不是**「仓库里现在是干净的」。
> 存量要另外管——这就是本 TODO 存在的理由。

## ✅ 4 条 Maven 的 medium 已清（2026-10-05）——而且顺带抓到一个真 bug

`commons-compress` 1.26.0 · `commons-lang3` 3.18.0 · `log4j-api` 2.25.5 · `poi` / `poi-ooxml` / `poi-ooxml-lite` 5.4.0。

前提是**先补了 Excel 烟测**（`ExcelRoundTripTest`）：写一个小 xlsx 再读回来，走的是生产代码
同一条 easyexcel 路径，不碰数据库、留在单元层（不需要 Docker）。有了它才敢动版本。

🎯 **烟测第一次跑就抓到一个此前没人发现的真 bug**：

```
NoSuchMethodError: ZipArchiveOutputStream.putArchiveEntry(ZipArchiveEntry)
```

POI 5.2.5 会调这个方法，而 easyexcel 4.0.3 传递进来的 commons-compress 是 **1.24.0**，没有它
⇒ **Excel 导出一直是坏的**。而没有任何测试会真的解析 Excel，所以 CI 一直绿。

⇒ 修法（commons-compress → 1.26.0）**同时**修好 Excel 与两条安全告警（解压死循环 / Pack200 OOM）。

⚠️ 记住两点：

1. **POI 的三个构件要一起钉**（`poi` / `poi-ooxml` / `poi-ooxml-lite`）——只钉一个会版本错配，
   报的错和上面这个 NoSuchMethodError 是同一类；
2. **钉传递依赖用 `dependencyManagement`，不要写进 `<dependencies>`**——它们不是直接依赖，
   写进去会让人以为我们自己要用。每条都要写「为什么钉」。

## 没定的事

**1 · 清不清、清到哪一档**（优先级：中）

多数是**构建期**依赖（`vite` / `postcss` / `esbuild` / `@babel/core`），不进生产产物，
暴露面与 `jjwt` 那类运行时依赖完全不同；`adm-zip` 在 `quizzy-mobile` 里，要单独看是不是运行时用。

可选：① 只清 high；② high + medium；③ 先只清**运行时**依赖，构建期那批等大版本升级时带走。

**倾向 ③**，理由：构建期依赖的漏洞要能被利用，前提是攻击者能让你构建不可信输入——
单人项目不成立；而把它们硬升上去反而可能弄坏构建链。

**2 · 存量怎么持续可见**（优先级：中）

现在只有「开 PR 时看增量」这一条，存量**没有任何自动化提醒**。
可选：① 靠 GitHub 的 Dependabot alerts 邮件（已开，0 成本，但只在**新公告**时通知）；
② 加一个每周定时跑的全量扫描 job（`dependency-review-action` 在非 PR 事件上用不了，
得换 Trivy 或 `npm audit`）；③ 不做，靠人偶尔去看一眼 Security 页。

**倾向 ① + 偶尔人眼**，暂不加定时 job（会重回「噪音门禁」的老路）。
