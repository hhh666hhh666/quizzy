# 待办：历史作答统计重复计数

创建：2026-10-05 · 状态：待办 · 优先级：低

## 改动前被回改过的题，`question_stat` 里的计数偏高，且**无法回溯修正**

**现状**：2026-10-05 之前，「已作答的题可以回去改答案」是后端真实行为——接口允许、文档也这么写，每次重复提交都会把 `question_stat` 的 `answer_count` 加一次、必要时连 `correct_count` 一起加（见 `QuizService#updateStat`）。**当天已改成「一题一答」**（[ADR 0022](../adr/0022-answer-is-final.md)），新数据不会再偏高，但**已经落库的偏差仍在**。

**为什么修不了**：覆盖发生在 `quiz_answer` 那一行上——它只保留最后一次的答案，被覆盖了几次、覆盖前是什么，都没有留痕。所以「哪道题被重复计过、计了几次」已经算不出来。

**可选方案**：

- **甲（倾向）不动，只留档**：偏差只影响历史会话的聚合数字与错题本排序，不影响判分逻辑，也不影响新数据。自用工具、历史量小，为它做一次数据手术不划算。留着这条记录是为了**下次看到某道题的正确率对不上时，知道背后有这样一段历史**，不至于当成新 bug 去查。
- **乙 按 `quiz_answer` 全量重算**：把 `answer_count` / `correct_count` 按「每个 (session, question) 计一次」重新聚合。⚠️ 它**不是还原**——只是把每道题折算成一次，等价于**假设历史上从没被回改过**；而真有过多轮练习的题，本来就该计多次。两种情况的原始信息都没了，区分不出来，重算等于用一个新的猜测换掉旧的偏差。
- **丙 清空统计重来**：连错题本一起清空，等于放弃已有的练习进度。不建议。

**为什么现在定不下来**：方案乙看起来「能修」，实际做不到；甲是荧的倾向，但要不要为一段只影响展示的历史偏差留一条长期待办，值得主人过一眼再定。
