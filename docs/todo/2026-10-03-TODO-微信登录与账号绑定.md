# 待办：微信登录与账号绑定

创建：2026-10-03 · 状态：待办 · 优先级：中

## 小程序用微信登录还是继续账号密码？

[ADR 0019](../adr/0019-mobile-clients-with-uniapp.md) 已定：移动端与小程序**先复用** `POST /api/auth/login`（用户名密码 + 无状态 Bearer JWT），微信登录**后置**。本待办记的是「后置的那块到底怎么做」还没定。

**现状**：后端只有账号密码登录（BCrypt 存储 + 无状态 JWT，无 refresh token、有效期 7 天）；小程序端还没有代码。

**为什么现在定不下来**：小程序上线前不必定；且它依赖备案这个外部前置（见 [`docs/todo/2026-10-03-TODO-备案与HTTPS.md`](./2026-10-03-TODO-备案与HTTPS.md)）。

**可选方案与倾向**：

- **继续账号密码登录**（小程序内输用户名密码）：零后端改动，但小程序里输密码体验一般。
- **微信登录 + 绑定已有账号**（若是真要小程序登录，倾向这条）：`wx.login → code2session → openid/unionid`，与现有账号绑定。

**做这件事时还要一起定的**：

- `openid` / `unionid` 落哪张表，要不要新表
- 能否解绑；一个账号能否绑多个微信
- 无手机号 / 无邮箱时账号归属与找回
- 与 [`docs/todo/2026-10-01-TODO-邮箱验证.md`](./2026-10-01-TODO-邮箱验证.md) 的关系——两条都可能改登录体系，别各做各的
