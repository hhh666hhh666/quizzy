# 共享分类的归属校验：已决定（改为「分类的生命周期跟着题目」）

**发现**：2026-10-04 · **决定**：2026-10-04（主人拍板）· **状态**：已实现

## 当时的风险

分类是**全体共用**的一套（CONTEXT.md），`Category` 没有 ownerId 是设计；但整个分类模块
**没有任何归属校验**，而 `CategoryService#delete` 会先 `clearCategory(id)`——
把**所有用户**挂在该分类下的题目引用一起清空。

服务已按 [ADR 0017](../adr/0017-public-signup-service.md) 对公网开放，于是：

> 任何一个注册用户都能删掉全体共用的分类，并让所有人的相关题目一次性失去分类归属。

补充两点事实（决定了后面的方案）：

- **前端没有任何删除入口**：`deleteCategory` 写在 `api/question.ts` 里却没人调用（死代码），
  移动端根本没有 —— 所以触发门槛是「发一条 HTTP 请求」，不是「点一下」；
- **用户在界面上也建不出分类**：唯一的入口是新建题目对话框里那个 `allow-create` 下拉，
  而它绑的是 Long 类型的 `categoryId`，输入新名字会直接失败。

## 决定：不给删除加校验，而是**取消主动删除**

讨论中主人指出两条荧原先没想到的：

1. **创建分类的前提是创建题目** —— 不该是「先建分类再建题」两步，那样会留下「只有分类没有题目」的残局；
2. **改分类名也不该原地改** —— 原地改会让**所有人**的题目都换名字。

于是定下：**分类的生命周期完全跟着题目**。

| 动作 | 现在的做法 |
|------|-----------|
| **诞生** | 随「保存题目」按**名字**自动建（同名复用 —— 撞别人的名字不是冲突，而是**合并**） |
| **改名字** | 只**迁移调用者自己的题目**到目标分类；别人的题留在原分类 |
| **消亡** | 不再被任何题目引用时，由系统自动回收（`CategoryService#pruneIfOrphan`） |
| **主动删除** | ❌ 端点已关闭（没有任何注册用户能删共享分类） |

接口只剩 `GET /api/categories`（列表）与 `PUT /api/categories/{id}`（改分类名）。

## 两条必须记住的推论

1. **规则卷里的分类不存在时，那条条件自动失效**（`PaperService#selectQuestionsByRule`）。
   不是让整张卷一道题都抽不到——否则用户只看到「没有符合要求的题目」却不知原因。
   论证：规则卷按分类抽题，能抽到题 ⟺ 存在该分类的可见题目 ⟺ 分类有引用；
   所以「引用为 0」时引用它的规则卷**本来也抽不到题**——而这个论证只在**不涉及改 id** 时成立。
2. **改分类名只迁移自己的题** ⇒ 若别人也在用旧分类，结果是**两个分类并存**：
   我的题在新分类、别人的题在旧分类（旧分类因此不会被回收）。这不是 bug，
   是「你只能动自己的归属，动不了别人的」。

## 断言已钉住

`CategoryApiIT`（分类随题目诞生 / 同名复用 / 改分类名只迁移自己的 / 删除端点已关闭）、
`CategoryServiceIT`（无人引用自动回收 / 有别人引用则不回收）、
`PaperServiceIT`（分类不存在时规则卷仍能抽到题）、
`QuestionServiceIT`（按名字建分类且同名复用、`categoryName` 空白 = 没填）。

## 不再另开「无人引用的分类自动清理」的 todo

主人决定这次直接做掉了（就是上面的「消亡」一条），所以不再单独挂 todo。

## 2026-10-05 追加：改分类名的**提示文案**又对齐过一次

主人提出把提示语改成「该选项会修改该分类下所有题目的分类」。⚠️ 那句话描述的是**另一个行为**——
「所有题目」按字面含别人的题，等于把上面那张表的「改名字」一栏推翻成「原地改名」，而那正是当初被否掉的做法。

结论：**只改文案、不改行为**。文案改成直白版的「会把你在这个分类下的全部题目迁到新分类；别人的题目不受影响。」
——与表里那一栏说的是同一件事，只是旧文案又长又绕。理由：界面上写一句后端并不这么干的话，
等真有第二个注册用户时，点下去就会发现别人的题根本没动，而提示语刚刚承诺过会动。

如果哪天真的要改成「连别人的题一起迁」，那是一次**推翻本文件结论**的变更，代价清单：
`CategoryService#moveTo` 去掉 `owner_id` 条件、`CategoryApiIT` / `CategoryServiceIT` 里
「只迁移自己的」那几条断言要改、本条要标成「已推翻」，并且**先回答**「服务对公网开放时，
任何人能改别人的题目归属是否可以接受」——这个问题的答案当初是否。
