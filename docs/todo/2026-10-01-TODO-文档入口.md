## 要不要在仓库根目录放一个 `CONTRIBUTING.md` 转发页

**现状**：协作指南在 [docs/development/contributing.md](../development/contributing.md)。
GitHub 只自动识别**仓库根目录**的 `CONTRIBUTING.md`，并会在开 PR 时显示「请先读贡献指南」的提示条；
放在 `docs/development/` 下不会触发那个提示。

**为什么现在定不下来**：本仓库是单人自用、外部 PR 极少（真有人想提，文档里也建议先开 issue），
提示条带来的收益接近于零；而多一个根目录文件就多一处要跟着改的地方——根目录那个 `DESIGN.md`
正是先当转发页、后来彻底没用被删掉的（见 [docs/README.md](../README.md) 开头的说明）。

**可选方案**：

- **A. 不放**（倾向）：靠 [docs/README.md](../README.md) 的文档地图指过去。代价是外部 PR 时不给提示条。
- **B. 放一个转发页**：只写一句「贡献指南在 `docs/development/contributing.md`」。
  承担与 `DESIGN.md` 转发页同样的负债风险。

倾向 A。**触发条件**：出现第一个真实的外部 PR 时再建。
