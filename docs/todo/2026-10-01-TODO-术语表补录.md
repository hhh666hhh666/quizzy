## 「关于」/版本号那轮定下的叫法，要不要补进 `CONTEXT.md`？

**现状**：2026-10-01 的「关于」功能 + 版本号治理那轮 grill 定下了几个新说法，现在散在两处：

| 说法 | 现在在哪 |
|------|----------|
| **版本号** | 已落进 [CONTEXT.md](../../CONTEXT.md) 的「版本与发布」小节 |
| **镜像 tag** | 只在 `docs/decisions/version-and-about-feature.md` 的「本次定下的叫法」里 |
| **构建期注入** | 同上 |
| **领先信息（副行）** | 同上 |

而「镜像 tag」这个词其实已经在 `CHANGELOG.md` 与 `docs/operations/deployment.md` 里被正式使用，
却没在术语表里定义过。

**为什么现在定不下来**：术语表归 `domain-modeling` 管，补录要跑一遍那个流程——它顺带还要判断
这几条算不算真术语、会不会与已有条目冲突、`_Avoid_` 该列哪些反例。而这三条里至少两条是
**实现细节的名词**，未必都够格：`CONTEXT.md` 现在收的全是领域概念（题目、试卷、会话、错题本），
混进构建术语会把那张表弄脏。这个界限该由跑 domain-modeling 时当场判断，不该在这里先拍。

**可选方案**：

- **A. 只补「镜像 tag」（倾向）**——它会被反复使用，且 `_Avoid_` 能写得很实（版本号、构建号、
  包版本）。另两条留在决策日志里即可：「构建期注入」是手段不是概念，「副行」是 UI 部件名。
- **B. 三条全补**——术语表更全，但会引入非领域词，稀释现有纯度。
- **C. 都不补**——保持术语表只收领域概念；代价是「镜像 tag」继续在别的文档里裸用，
  三个月后得回翻决策日志才明白它指什么。

**倾向**：A，作为一次单独的收尾会话跑 `domain-modeling`——补录不是随手加几行字的事，不顺手做。
