## 备份最终放哪儿

现在临时落在项目内的 `.backup/`，由 `.env` 的 `BACKUP_DIR` 控制（见 `scripts/backup-mysql.sh`）。

⚠️ **但 MySQL 数据在 `E:\develop\docker\mysql8`，项目也在 E 盘，备份和数据是同一个故障域**——E 盘挂了两边一起没。这只能算「复制」，不算「备份」。

有结论后挪到别的盘。本机盘位：C 只剩 11G（96% 满），D 剩 85G，E 剩 213G。**D 盘是目前唯一合理的选择**。

## 谁来触发定时备份

`scripts/backup-mysql.sh` 写好了也实测跑通了，但没挂到任何调度上。两条路：

- **Windows 任务计划程序**：不依赖任何 Agent 在跑，但排障不方便
- **这里的自动化定时任务**：改起来方便，但 Agent 不在的时候不会执行

倾向前者——备份不该依赖一个会关掉的东西。定了之后把调用命令写进这个文件。
