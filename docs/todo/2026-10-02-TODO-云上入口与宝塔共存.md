# 待办：云上入口与宝塔共存

创建：2026-10-02 · 状态：已解决 · 优先级：高

## 结论（2026-10-02）：选 A —— 让宝塔的 nginx 做对外入口

主人选定 **A**。落地形态：quizzy 的 web 容器只绑 `127.0.0.1:8081:80`，在宝塔里新建站点反代过去，证书交宝塔。

**顺带拿到的净收益**：原计划的 `acme.sh` + DNS-01 整条链路取消——宝塔自带 Let's Encrypt 申请与自动续期，
于是**不必再把一个仅 DNS 权限的 RAM AccessKey 放在服务器上**。这条是选项 A 的附带结果，不是额外代价。

**接受的代价**：对外多一层 nginx；站点配置归宝塔管、位于仓库之外，成为新的「仓库外配置漂移源」。

## 原始记录（2026-10-02，决策前）

## 80 / 443 被服务器上既有的宝塔面板占用，quizzy 的对外入口怎么设计

**现状**（2026-10-02 实测 `8.137.172.6`）：这台轻量服务器上装着**宝塔面板 11.2.0** 并且正在运行——
它的 nginx 1.28.3 占着 `80` 与 `888`，面板自身在 `7891`；`443` 空闲；
宝塔的站点目录 `/www/server/panel/vhost/nginx/` 里**没有任何站点配置**，说明还没建过站。

而 [ADR 0016](../adr/0016-cloud-deploy-with-release-pipeline.md) 设计的形态是 quizzy 的 web 容器
自己 hold `80:80` 与 `443:443`——**会与宝塔的 nginx 直接冲突**。

**为什么现在定不下来**：得先知道这台机器是否还归宝塔管、主人是否还要用它建别的站。
这不是技术好坏问题，是「这台机器谁来管」的问题。

**可选方案与倾向**：

- **A · 让宝塔的 nginx 做对外入口** ← **倾向这个**：web 容器只绑 `127.0.0.1:8081:80`，在宝塔里新建站点反代过去。
  附带的大好处：**HTTPS 那整套 `acme.sh` + DNS-01 可以砍掉**——宝塔自带 Let's Encrypt 申请与自动续期，
  也就不必把 DNS AccessKey 放在服务器上（[ADR 0016](../adr/0016-cloud-deploy-with-release-pipeline.md) 里记的那个唯一代价随之消失）。
  代价：对外多一层 nginx；站点配置归宝塔管、位于仓库之外，成为新的「仓库外配置漂移源」。
- **B · 停掉宝塔的 nginx，让 quizzy 容器直接占 80/443**：架构与 ADR 0016 完全一致，配置全在仓库里可版本化。
  代价：破坏宝塔的网站功能（面板本身在 7891 上，不受影响）。
- **C · quizzy 走非标端口**（如 `8443`）：零冲突、零破坏。代价：正式站点地址带端口，且备案审核看的是 80/443。

**顺带记一条安全提醒**：宝塔面板监听在 `0.0.0.0:7891`，即对公网开放。这台机器马上要承载一个公开注册的站点，
面板端口应收紧到指定来源 IP（或改走 SSH 隧道）。这属于「主人自己的机器怎么管」，荧不擅自改。
