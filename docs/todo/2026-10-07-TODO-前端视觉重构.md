## 1. 中文字体：要不要自托管子集

**现状**：重建时先用**系统字体栈打底**，字体在 token 层留出变量位（一个 `--font-family` 与一套字阶）。
**为什么现在定不下来**：自托管中文子集要选字、切子集、管许可、防 FOIT，成本明显；而「精美」的收益主要来自排版尺度 / 间距 / 颜色，字体是锦上添花且可后补。
**可选方案**：**A 先不动**，等浅色版整体成型后回看效果再决定（**倾向**）；B 现在就上（如思源黑体子集）——除非明确觉得系统栈不好看，否则不值得提前付这个成本。
（重建已收官：浅色版即当前线上形态——**可以正式做这个决定了**。）

## 2. 文档组织：出现「文档打架」时再看情况重构

**现状**：按 ADR 0031，仓库根已有 `PRODUCT.md`（受众 / 目标 / 品牌承诺）与 `DESIGN.md`（视觉系统，派生快照，2026-10-08 由 `impeccable document` 生成）；它们的部分内容与 [`scope.md`](../requirements/scope.md) **已知重叠**，**冲突时以 `scope.md` 为准**。`docs/design/` 的目录组织也维持原样。
**为什么现在定不下来**：重叠是**知情的取舍**（换"就地划清"要多轮对齐，收益不及成本）；真正该动手的信号是**出现实际冲突**，而不是预设一次目录重组。
**触发条件**：**当同类内容在两处对不上、且已经影响到实际判断时**，回来考虑重构文档组织（含 `docs/design/` 与根 `PRODUCT.md`/`DESIGN.md` 的分工）。
**可选方案**：A 到那时再定（**倾向**）；B 现在就把边界划死（`PRODUCT.md` 只管受众 / 语气 / 视觉约束，`scope.md` 只管功能范围与不做，两处互指）——若第 1 次真撞上，就走 B。

## 4. 辅助文字档（`ink-subtle`）的小字口径（2026-10-08 已定、已执行）〔已结案〕

**口径（方案 A）**：**保留值**；`ink-subtle` 限定为**仅大字（≥19px 粗体）/ 装饰**，有信息量的小字一律用 `ink-muted`——口径在 `quizzy-web/src/styles/tokens.css` 该档的注释里。
**执行（2026-10-08 结算）**：预览页的 31 处小字已全部换成 `text-ink-muted`；重建后的新组件从第一天遵守该口径。本项**结案**。

## 5. 存量浮层是否换玻璃（2026-10-09 口径修正后转为逐件自定）〔已结案〕

**原问题**：ADR 0032 初稿曾定「浮层一律玻璃」，与「玻璃上不许放长正文」及题目详情弹窗（题干 / 解析长正文）正面相撞。
**结案（2026-10-09 主人二次口径）**：玻璃是**逐件可选**材质，不搞一刀切；**唯一硬禁令是答题页面（作答中）不用玻璃**。「长正文弹窗 × 玻璃」的矛盾随之消解——实底本来就是合法选项，存量浮层（题目详情 / 确认框 / 下拉…）**不强制迁移**，是否换玻璃逐件看实体预览拍板。当前已用玻璃的只有「收藏夹信息」面板。

## 6. 外部 AI 对收藏夹页批评的处置（2026-10-09 已结算）〔已结案〕

主人从另一个 AI 收到一份对旧版收藏夹页的批评（视觉扁平 / 操作裸露 / 圆角 / 徽章计数等约 15 条），逐条核账的结论：
- **采纳 3 条**：操作收进「⋯」菜单、行间距放宽、层级两块面（v3 构图）。
- **改法不同 3 条**：新建按钮保持描边（实色主按钮违反「主色一页一处」）；选中态在 tint 面上用**近白浮起卡 + 3px 主色条**（`brand-soft` 叠在 tint 上仅 1.05:1，纯底色差不可见——外部 AI 的「实色蓝底白字」同样违反晕底口径）；计数保留 tabular 数字文本（徽章违反「Chips 只表类型」）。
- **不采纳 5 条**：4–8px 圆角（事实性误读，标尺 5–24、卡 20）、去星标换图标、顶部操作栏、卡片化全部列表项、hover 才显操作（触屏 / 键盘够不着——⋯ 按钮常驻 DOM、触屏常显）。
产物：收藏夹页 v3 重构 + ADR 0032 + 「收藏夹信息」玻璃面板（含后端 `intro` / `is_public`）。参照图与 Stitch 产物属一次性参照，不入库。
