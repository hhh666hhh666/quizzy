## 深色模式（移动端未做）

**现状**（2026-10-06 记）：PC 端 `quizzy-web` 已上「跟随系统 / 浅色 / 深色」三档外观，机制见
[《前端》](../design/前端.md)。移动端 `quizzy-mobile` 本轮**刻意没做**——主人只要求 PC 端。

**真做时要看的三个点**：

- wot-design-uni **自带**暗色皮肤，最外层挂 `wot-theme-dark` 即整体变色，组件不用逐个改；
  工作量全在**自有样式**——色值要换成可随主题切换的 CSS 变量（现状盘点以 `quizzy-mobile/src/` 为准）。
- 顶部标题栏颜色写在 `pages.json` 里、是**静态**的，深色下得用 `uni.setNavigationBarColor` 动态改。
- 代码高亮要补一套暗色（该工程的 `MarkdownRenderer.vue` 引的是浅色 `github.css`）。

跨端写法上，把 `wot-theme-dark` 挂在页面根节点比直接操作 DOM 更通用（H5 与小程序都吃）。

**为什么现在定不下来**：移动端不在本轮范围；且 `mp-weixin` 编译目标与 `/m/` 部署本身尚未落地
（见上面那节），深色模式宜与那两件事的形态一起定，免得写两遍。

## 其余页面的顶部头部是否统一（2026-10-10 新增）

**现状**：答题页已改为自绘浅色品牌头（`quizzy` 字标 + 放弃本次，`navigationStyle: custom`，
见 [ADR 0033 Amendment 1](../adr/0033-mobile-visual-unification.md)）；其余七个页面（首页 / 登录 /
快速练习 / 结果 / 错题本 / 记录 / 试卷）仍是系统蓝条导航栏。挑中的设计稿只覆盖答题页。

**两个方向**：

- **保持现状（偏此）**：答题页是「专注流程屏」，无返回是设计意图；子页面保留系统导航栏才有返回入口。
- **全站统一**：所有页面换浅色品牌头——子页面的「返回」入口怎么画要连带定（新设计点），
  改动面大，建议先补一版头部稿再动手。

➡️ **倾向**：暂维持现状。要统一时先出稿、后落地，别边改边想。

**待确认**：主人拍板要不要统一（差异与理由荧已在 2026-10-10 的汇报里说明）。
