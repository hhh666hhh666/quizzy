# 待办：移动端与小程序落地

创建：2026-10-03 · 状态：待办 · 优先级：高

## 建 `quizzy-mobile`、先跑通 H5、再上小程序

移动端的**架构**已定在 [ADR 0019](../adr/0019-mobile-clients-with-uniapp.md)：uni-app（Vue3）单工程编译 H5 与微信小程序，PC 端 `quizzy-web` 不动，移动端只做「消费」。本待办记的是**落地**这件事还没做。

**现状**：`quizzy-mobile/` 目录尚未创建；移动端设计只有一份骨架（[《移动端》](../design/移动端.md)，现阶段它是唯一真相源）。

**为什么现在定不下来**：架构收敛这一轮刻意不写代码（见 [决策日志](../decisions/mobile-and-miniprogram.md) D4），落地要排到之后；且一批实现级选择还没有答案。

**可选方案与倾向**：

- **先 H5 后小程序**（[ADR 0019](../adr/0019-mobile-clients-with-uniapp.md) 已定）：备案没下来，小程序上线遥遥无期，H5 能最快兑现「手机上用」。
- 两端并行：收益不明显，反而是把外部阻塞引进开发节奏。

**落地时要一起定的（现在都不定）**：

- uni-app 的版本、Vue3 + TS + Vite 的脚手架方式
- 移动端组件库选型（Element Plus 在 uni-app/小程序里用不了，换 uni-ui / uView / wot-design-uni 一类）
- 移动端导航形态与设计规范（底部 Tab / 抽屉 / 手势）
- `quizzy-mobile` 要不要照 PC 配 `typecheck + build` 同类 CI 门禁
- H5 的 `/m/` 与 PC 同域部署（nginx 路由）——上线时同步 `docs/operations/deployment.md`
