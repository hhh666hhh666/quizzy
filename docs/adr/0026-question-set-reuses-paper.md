# 「题集」需求复用试卷，不新增题目集合实体

Status: accepted

2026-10-06 提出的原始需求是「加一个题集功能：自己可以创建题集，往里添加已有或未有的题目；通过 Excel/JSON 导入时可选择是否为这批题建一个题集并加入」。盘点后发现，现有**固定卷**（`paper` 的 `FIXED` 模式 + `paper_question` 关联表）已经是「有名字、手动选题、可反复发起作答的组合」——正是需求里描述的「题集」。于是决定**不新增 `question_set` 之类的实体**：题集需求一律由试卷（固定卷）承载，改为补齐它现有的三处短板。

## Considered Options

- **新增独立「题集」实体**（`question_set` + 关联表），与试卷并存：与固定卷功能重叠约九成；且「题集」在 [CONTEXT.md](../../CONTEXT.md) 里本就是「试卷」的**禁用别名**。两套概念并存，日后必然要为「题集里的题和固定卷里的题删了要不要互相同步」这类没有价值的问题买单，所以否掉。
- **把「试卷」整体改名「题集」**：试卷有两种形态（固定卷 / 规则卷），改名后规则卷也叫「题集」，语义更拧；还要连带改术语表与一批设计文档，而收益只是换一个词。否掉。
- **只在题库 / 导入入口的文案叫「题集」，试卷页仍叫「试卷」**：同一概念两套叫法，是术语表最忌讳的形态。否掉。
- **复用固定卷（选定）**：零新概念、零迁移，`paper` / `paper_question` 现成；需求要的能力靠补现有短板即可达成。

## Consequences

- 「题集」**仍然不是本项目的术语**：`CONTEXT.md` 里它继续是「试卷」的禁用别名。以后再看到「题集」字样，先按「试卷」理解。
- 为了真正满足需求，要补**三处现有短板**（原先都不存在）：
  1. 固定卷的**选题器**——原先只拉第 1 页前 100 条，无搜索、无筛选、无翻页，题一多就找不到；
  2. 固定卷原先**必须至少选一题**，要放宽以支持「先建空卷、后加题」；空卷**不可作答**（服务端本来就有兜底，前端把它置灰）；
  3. 题库页原先**零多选、零批量**，要加「加入已有试卷」与「用选中题目新建试卷」两个动作（前者需要新接口）。
- 导入时顺带建卷的元信息走**查询参数**（`paperTitle=`）而非把 JSON body 改成包装对象——这条更正了 [ADR 0006](./0006-bare-array-import-contract.md) 的一条 Consequence，见该卡 **Amendment 1**。
- ⚠️ 导入**无查重**是既有取舍（见 [《导入导出》](../design/导入导出.md)）：勾选建卷后重复导入，会同时产出重复题目与重复试卷。这不是本条引入的问题，也不在本条的解决范围。
- **将来若真出现「不用于作答、纯归类」的容器需求**（例如跨用户可共享的题单），那才值得新开一条 ADR 并新增实体。本条的结论不阻碍那个方向，只是不提前建。
