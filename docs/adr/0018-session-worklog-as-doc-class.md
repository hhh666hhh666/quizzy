# AI 会话的过程记录单独建一类文档

Status: accepted

`docs/` 下新增 `docs/worklog/`：**AI 会话的过程记录，一次会话一份**，动手之前先建、随进度更新。配套一条总是加载的规则 `.codebuddy/rules/session-worklog.md`（触发条件与硬边界）与一份常驻的 `docs/worklog/README.md`（模板）。起因是既有的两条纪律都只覆盖**结论**——未决事项归 `docs/todo/`、决策归 `docs/adr/` 与 `docs/decisions/`——**没有一类管"过程"**。一次长任务的"现在做到哪了"原本只存在于对话里，对话一关就没了。

## Considered Options

- **复用 `.workbuddy/memory/`**：那里已在按天记工作日志，且被 gitignore。但它是**按天聚合、多会话共用一份**（2026-10-01 那一天被六次不同会话追加过 `补记一`～`补记六`），会话之间必然互相踩。工作台的诉求恰恰是**按会话隔离**，两者是分工不是重复。
- **不进版本控制（加进 `.gitignore`）**：最贴合"只在对应会话有意义"，而且实测 `check-doc-links.sh` 只扫 `git ls-files`，不入库就永远不会被 CI 扫到、零断链风险。**被否**：换台机器就看不到，而诉求正是"随时能打开看看"。
- **只写进 `docs/`，不立规则**：零规则开销。**被否**：没有强制加载，后来的 AI 根本不知道这条规范存在，要它执行就是空谈。
- **入库 + 一条独立规则**（选定）：代价是公开仓库里会持续堆 AI 的过程文档，以及工作台必须遵守更严的边界（见下）。

## Consequences

- **它补的是"过程"，不是"结论"。** 未决事项仍归 `docs/todo/`，决策仍归 `docs/adr/` 与 `docs/decisions/`；与 `docs/` 冲突时以 `docs/` 为准——**它是过程，不是事实源**。
- ⚠️ **「会话结束」判断不了，所以这个状态不存在。** AI 拿不到会话结束事件，只有回合结束。原设计的"标已结束"是个永远写不进去的死字段，正是 [ADR 0014](0014-ai-discipline-in-repo.md) 记的那类**静默失效**。改用三个确实能知道的信号：**本轮状态**（进行中 / 等你确认 / 本轮完成）、**最后更新**时间戳（由人看时间推断）、**惰性归档**（判定为"新建"时扫目录，超 7 天未更新且未完成的标 `已归档（超期）`）。
- **"新建还是续写"与"何时归档"共用同一个判据**：上下文里有没有这份文件。不需要任何会话 ID——文件名里那个短串只为防撞车，不承担身份。
- **入库带来硬约束一：工作台里不写 Markdown 相对链接**，路径一律行内代码。`check-doc-links.sh` 会扫已跟踪的 md，而工作台天生随时删改，写成链接就会在别处报红。
- ⚠️ **硬约束二：不写任何"能从别处查到"的事实**，显式包括 **git 状态**（哪些已提交、commit 哈希、推送范围）。这条纪律项目本来就有（[ADR 0006](0006-bare-array-import-contract.md)），但**既有表述是枚举式的**（"能从代码、脚本、`.env.example`、Flyway、springdoc 推导的……"）——git 状态不在枚举里，于是第一份工作台就把它抄了进去，并且**当场抄错**（说"本行之后未提交"，实际上一行前也是）。
- ⚠️ **由此得到一条通用教训：新造的高频写入面会把既有纪律的盲区放大。** 工作台是每次会话都写、写完就提交的，写入频率比 `docs/` 下其他文档高一个量级。**新建一类高频写入文档时，要回头检查既有纪律的表述方式扛不扛得住它。** 本次的修法是把 `docs-sync.md` 的单一信息源从枚举式改成**判据式**（"真相源是不是某个随时会变的东西"），判据才能自动覆盖以后才出现的信息源。
- **其他会话默认不读 `docs/worklog/`**。唯一例外是惰性归档，且只读每个文件前 10 行、只改状态那一行。
- **`docs/目录结构.md` 里 ADR 那一条不再写条数**。原来写"17 条"，而每加一条 ADR 就要回头改它——那是派生事实，正是 ADR 0006 禁止复制的东西。改成只写形态（`NNNN-*.md`）。

相关：[ADR 0006](0006-bare-array-import-contract.md)（单一信息源，本次两条硬约束都由它推出）、[ADR 0014](0014-ai-discipline-in-repo.md)（AI 纪律入仓、规则的体积硬约束与静默失效）。
