# 逐题即时判分，作答进度直接落 MySQL

一次会话的题目在发起时就全部落库，之后每答一题立刻判分并写回，刷新页面或关机都能接着做。没有引入 Redis 或任何会话缓存：单机自用场景下一次会话只有几十条记录，MySQL 的写入成本可以忽略，而多一个中间件就多一份需要解释、备份和排查的状态。

## Considered Options

- **前端暂存、最后一并提交**：实现最简单，但关掉浏览器就没了，与「随时中断随时继续」的要求直接冲突。
- **Redis 存会话草稿**：功能上可行，代价是要为一个人的练习引入缓存过期、持久化和又一个要维护的容器。
- **落 MySQL**：多一次写，但历史记录天然可查，未完成的会话也自然变成「答题记录」里可继续的条目。

## Consequences

- 每提交一题有一次数据库写入。题量很大时（比如一次几百题）可以改成批量提交，但当前规模下没必要。
- 历史记录与进行中的会话共用同一张表，靠状态区分，未完成的会话因此天然支持续答。
