# 改密码即全场下线：用 token_version 作废所有旧 token

Status: accepted

quizzy 的登录态是无状态 JWT（有效期 7 天），签出去就收不回来——改密码也踢不掉已经拿到 token 的设备。账户自助这轮要开放「改密码」，于是必须回答「改完密码，别人手里的旧 token 还算不算数」。结论：`user` 表加一列 `token_version`，签发 JWT 时把它写进 payload，校验时与库里的值比对；改密码、或点「退出所有设备」时 +1，所有旧 token 立即作废。

这条同时兑现了「一个账号可以同时登录多个设备」——平时各设备互不干扰，只有主动作废时才一起下线。

## Considered Options

- **永不作废**（保持纯无状态）：零改动。被否，因为账号一旦被盗用，改密码也踢不掉对方。`scope.md` 已把定位从「个人自用」改成「对公网开放」（[ADR 0017](0017-public-signup-service.md)），这个缺口在公开服务上不可接受。
- **设备会话表**：新增一张表记录每次登录（设备 / 时间 / 最后活跃），可以列出设备、单个踢下线。被否，因为要维护会话状态、每次请求都要查它，与 `scope.md` 的「不引 Redis / 不做后台管理」相冲；而「能看到设备列表」这个收益，在目前没有多端用户的情况下用不上。
- **token_version（选定）**：`user` 加一列整数，签发时写进 JWT，校验时比对。只加一列、不新增表，就换来「全场立即下线」。

## Consequences

- ⚠️ **每次带 token 的请求都要多查一次数据库**（把 JWT 里的版本号与 `user.token_version` 比对）。这是选中这条路的代价——登录态从此是「半状态」。目前规模下可接受；真成瓶颈时可在进程内缓存。
- 顺带解决了一件事：查不到用户（已被注销）时同样返回 401，所以**注销立即生效**，不需要额外机制。
- 改密码成功后，后端**直接给当前设备发一个新 token**，操作者本人无感；其他设备下一次请求就拿到 401。
- 「退出所有设备」按钮复用同一机制，实现几乎零成本。它是用户能主动使用这个能力的**唯一出口**——否则想踢掉一台不认识的设备，只能靠改密码。
- 升级是**无损**的：切换前签发的旧 token 不带这个字段，解析时按版本 0 处理，而库里默认值也是 0，所以存量登录态在 7 天有效期内照常可用，不会把所有人踢下线。
