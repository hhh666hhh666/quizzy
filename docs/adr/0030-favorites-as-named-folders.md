# 收藏用「多个具名收藏夹」表达，且「收藏」等于「在至少一个夹里」

Status: accepted

要给题目加收藏能力。结论不是「一个收藏开关 + 一个收藏列表」，而是**收藏夹**：一个用户可以有多个具名收藏夹，一道题可以同时放在多个夹里；而「**收藏**」这件事被定义为「**它至少在某个夹里**」——不存在独立于收藏夹的收藏状态，也就不存在「未分组」这个中间态。为了让「随手收藏」有一个不必当场思考的落点，每个用户**天然拥有一个「默认收藏夹」**：点星标直接进它，再通过横幅上的「修改收藏夹」把它挪到别处。

## Considered Options

- **单一清单**（一道题要么被收藏、要么没有，「收藏夹」只是那个列表页的名字）：改动最小，还有错题本可照抄。被否是因为主人要的是「收藏**夹**」——按主题分组正是这次的主要诉求，而分组无法事后无痛补上（单一清单升级成多分组要做数据迁移）。
- **收藏是独立状态 + 收藏夹只是附加归类**（于是有「收藏了但没归类」的「未分组」态）：语义最松、随手收藏毫无压力。被否，因为它凭空多出一个中间态——这个中间态在界面上必须有个说法，等于多一层概念；用「默认收藏夹」兜底能达到同样效果，而概念更少。
- **一道题只能进一个夹**（给题加一个「所属夹」列，少一张表）：被否，因为它是选定方案的**真子集**，而且反悔方向是单向的——多夹收窄成单夹只要加一条约束，单夹放宽成多夹却要数据迁移。同一条理由也适用于「留一个可空列、以后再拆表」那种折中。
- **多个具名收藏夹，且「收藏」= 在至少一个夹里**（选定）：两张表，`favorite_folder` + `favorite_folder_question`。

## Consequences

- 收藏**无法从任何现有表投影出来**——错题本是 `question_stat` 的投影，而收藏是用户的主动选择、不是作答的结果。所以它必然新增两张表，这是它与错题本在范式上最大的不同（对比 [《数据模型》](../design/数据模型.md) 的「会话、作答统计与错题本」一节）。
- **「默认收藏夹」按需创建**（用户第一次收藏时若还没有就建一个），于是**不需要给存量用户做数据迁移**。它**不可删除**（否则随手收藏无处可落）、**可以改名**——所以「默认收藏夹」这五个字**不许写死进任何界面文案**，横幅要显示它当时的名字。
- 夹名**同一用户内唯一**（DB 唯一键）。这与「昵称允许重名」并不冲突：昵称是别人怎么称呼主人（本项目界面里根本看不到别人的昵称），而夹名是主人自己挑东西时的路标，两个同名夹必然点错。夹名长度上限 20 字、**不设数量上限**。
- **夹列表按「该夹最近一次有新题进来」的时间倒序**，且这个时间**不存冗余列**——从关联表按 `max(create_time)` 聚合出来。存一列冗余的「最后使用时间」会在删题、改归属这些路径上一点点漂掉，而那正是本项目最忌讳的那类失效（[ADR 0006](0006-bare-array-import-contract.md)）。
- **删掉一个夹只会把题从它里面移出**；题目若因此不再属于任何夹，就不再是收藏。代价是「删夹」在题目的视角上可能等于「取消了收藏」，界面上必须说清。
- ⚠️ **星标用两种手势**：**短按** = 收藏（进默认夹）/ 取消收藏（从所有夹移出）；**长按**（约 500ms）= 打开「修改收藏夹」面板。选它，是因为一个星标被要求同时承担「开关」与「改归类」两件事，而「改归类」不该让每次随手收藏都多一步。**代价要认**：长按在桌面浏览器里几乎没有可发现性——所以横幅上的「修改收藏夹」按钮才是明路，长按只当快捷键；另外长按必须抑制随之而来的短按，并阻止浏览器的文本选择。
- 「修改收藏夹」面板是**覆盖**语义且**不预勾当前状态**：勾谁就属于谁；**一个都不勾 = 留在默认夹**，而不是取消收藏——否则一次手滑就丢掉收藏。这也让「空选」有了安全兜底。
- **短按取消收藏给一次「撤销」**：被移出的那几个夹由后端在删除响应里返回，客户端记住它们，撤销即原样加回。纯客户端实现，**不新增接口**。
- 收藏的新题**落进默认夹**时弹一条横幅，而不是静默成功——否则主人不知道它去了哪。
- ⚠️ **只落 PC**。收藏是一次新的写操作，属 [ADR 0019](0019-mobile-clients-with-uniapp.md) 说的「新增业务能力」，而移动端只做消费。
- 「来源」多出第四种：**收藏练习**（`SourceType.FAVORITE`）。它作用于「当前选中的那个桶」，包含「全部收藏」。
