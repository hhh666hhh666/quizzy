# dev / prod 两套 compose，MySQL 数据绑定挂载到宿主机

Status: accepted

开发态只起 MySQL，前后端在宿主机跑（改代码不用重建镜像）；生产态前端、后端、数据库全容器，一次 `up` 就能起来。两者共用同一份数据：MySQL 的数据目录**绑定挂载**到宿主机磁盘，而不是用命名卷——这样容器重建、切换编排文件、甚至 Docker 本身出问题，题库都在磁盘上肉眼可见、随手能拷走。

## Considered Options

- **命名卷**：Docker 推荐做法、性能最好，但数据藏在 Docker 内部路径里，出问题时要靠 `docker cp` 才能拿出来。
- **开发态也全容器**：环境最一致，代价是每次改一行代码都要重建镜像，本地开发基本没法用。
- **绑定挂载**（选定）：牺牲一点点 I/O，换来数据随时可见可搬。这是个人项目的题库，值。

## Consequences

- 两个编排文件里的 MySQL 容器同名，切换前必须先 `down`，否则会启动失败。
- 数据在宿主机意味着备份策略要自己做，Docker 不会替你管。
- 挂载路径带盘符，compose 里必须用长语法写绑定挂载，短语法会被盘符里的冒号切错。
- 尚未拍板：是否给前后端容器加 healthcheck、数据定期备份、镜像 tag 与分发方式。
- 相关：0009（构建镜像必须 glibc 且要有 .dockerignore）、0010（构建期依赖走国内镜像源）、0011（配置抽到 .env 并保留本机默认值）。
