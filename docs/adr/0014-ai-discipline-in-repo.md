# 把「AI 协作纪律」写进仓库，并用 CI 兜底

Status: accepted

对话会关、上下文会被压缩，但仓库不会。之前踩过两次：一是「未决事项」散落在会话里，要靠回看决策日志才知道「当初到底定了没」；二是移动或删除文件后，注释和脚本里的路径静默失效（`DESIGN.md` 拆分那次就是逐个 grep 才补齐的）。

所以把两条纪律固化进仓库：**未决事项必须落盘 `docs/todo/`**，**改代码必须同步改文档**。形态是三件套——`.codebuddy/rules/` 下两条总是加载的规则（软约束，让 AI 知道）、`.codebuddy/commands/wrap-up.md` 收尾命令（流程，让 AI 记得做）、`scripts/check-doc-links.sh` + CI job（硬约束，不做就过不去）。根目录 `AGENTS.md` 是给其他 AI 工具的精简摘要。

## Considered Options

- **只写在 `CONTRIBUTING.md` 里**：已经有一节「文档纪律」了，零新增文件。但 AI 不会主动去读它，等于写给未来的自己看，对 AI 无效。
- **只用 `.codebuddy/rules/` 规则**（不建脚本、不加 CI）：改动最小。但规则是提示词，是软约束——注意力衰减、上下文压缩之后它就会漂，而且**漂了没有任何信号**。
- **配 PostToolUse hook，每次写文件都自动检查**：最及时。但在 Windows 的 Git Bash 上全仓 grep 一次要几秒，频繁写文件的任务里会被拖垮；人的反应必然是禁用它，那就彻底失效。
- **三件套 + CI（选定）**：规则负责「知道」，命令负责「记得做」，CI 负责「不做过不去」。代价是多一个 job（只跑几秒，不需要任何 toolchain）和一个约 150 行的脚本。

## Consequences

- **规则的体积是硬约束**：`.codebuddy/rules/` 下的文件超限会**被整份丢弃**（只在日志里 warn，不报错），表现为「规则仿佛没生效」。所以两条规则各控制在 50 行内；新的规矩宁可新开一个带 `paths` 的条件规则，也不要往这两条里加字。
- **`AGENTS.md` 与两条规则存在内容重复**，是刻意的取舍：它是给不读 `.codebuddy/` 的工具用的。为控制漂移，`AGENTS.md` 明确写了「权威版本在 `.codebuddy/rules/`，冲突以那边为准」，且只放结论、不放解释。
- **检查脚本的误报比漏报更贵**。一旦 CI 开始报假错，人就会养成「红着也照合」的习惯，那比不检查更糟。所以第二阶段（脚本/注释里的路径引用）收紧在「顶层目录白名单 `docs/ scripts/ .github/` × 扩展名白名单」里，并留了 `--no-scan-refs` 兜底。
- **脚本的第二阶段是中文补出来的**：初版 token 只认 ASCII，会把 `docs/todo/2026-09-20-TODO-数据库备份.md` 这类路径全漏掉——而中文文件名恰恰是本仓库最容易失效的一类引用。
- **Windows 上跑这个脚本天然很慢**（Git Bash 每起一个进程要几百毫秒）。实现上要避免逐文件起进程：`$(dirname)`、函数 + `$()` 都会 fork，两百多处引用就能到一分钟；改用 `xargs` 批量 grep + bash 内置展开后降到 6 秒。
- 谁都可以绕过：CI 只在 PR 上跑，直接 push master、或用 `--no-verify` 都能跳过。**它挡的是疏忽，不是故意**。
- 以后 WorkBuddy 若往 `.codebuddy/` 里写本地缓存或会话数据，要按**具体文件名**加 gitignore 例外，**不要整体忽略 `.codebuddy/`**——那会把规则本身一起忽略掉，且失效时没有任何提示。
