# 浮层材质口径放开（玻璃可选、答题页禁用）；收藏夹补齐「简介 / 是否公开」

Status: accepted

两件事同属一次改动，分开记会各丢一半上下文，故合并成一张卡。

**其一：浮层材质口径放开——玻璃成为可选，答题页明确不用。** [ADR 0031](0031-pc-frontend-rebuild-shadcn-vue.md) 的 Amendment 1 定的是「浮层 = 练习纸实底 + 1px 描边 + 遮罩压暗，**有意不用模糊玻璃**；轻玻璃只服务顶栏」。本次主人先拍板放开（浮层可用 `.glass`：`rgba(255,255,255,.68)` + `blur(18px) saturate(140%)` + 1px 白描边 + 24px 圆角 + 冷调宽影），**同日二次口径收窄定案**：玻璃是**逐件可选**的材质，不搞「浮层一律玻璃」的一刀切——**唯一硬禁令：答题页面（作答中）不用玻璃**；其他地方用不用玻璃逐件看实体预览拍板。「同类元素只准一种语言」的旧规矩随之一并放开。

**其二：收藏夹补两个字段**——`intro`（简介，≤200 字）与 `is_public`（是否公开）。起因是按新设计的「收藏夹信息」面板里，名称 / 是否公开 / 简介三项都要；`cover`（封面图）主人明确**不要**。

## Considered Options

**关于浮层材质**

- **维持实底（ADR 0031 Amendment 1 的原口径）**：对比度最稳、不赌 `backdrop-filter` 的实现差异。**被否**——主人看的是成品观感，「浮层透出背后内容」这层材质语言有它的价值；且顶栏已经在用轻玻璃，一刀切禁用显得武断。
- **浮层全部改玻璃**（一度被选）：**同日被主人二次口径收窄否掉**——「一律玻璃」变成新的强制，与主人「其他地方可能用也可能不用」的直觉相反；也把「玻璃上不许放长正文」与题目详情这类长正文弹窗的矛盾从「将来要解」升级成「现在就得解」。
- **只让下拉菜单用玻璃、弹窗仍用实底**：**被否**——按元素种类拆档，是把选择权从「逐件看预览」手里拿走交给一条死规矩。
- **玻璃作为逐件可选材质 + 答题页硬禁用**（选定，2026-10-09 定案）：用不用玻璃是**视觉决策**，看实体预览拍板、不写进一刀切规矩；答题页面（作答中）是唯一明确不用玻璃的地方——作答是全产品最要「稳」的界面，浮层透出背后内容只添乱。

**关于收藏夹字段**

- **只加「简介」**（`intro`）：**被否**——主人明确要「是否公开」（为将来分享 / 公开收藏夹留位）。
- **加 `intro` + `is_public`，不加 `cover`**（选定）。主人明确不要封面图：它要真的做出来就得有上传通道与存储方案（本项目无文件存储，头像都是塞进库里的 data URL），成本与收益不成比例。
- **加 `cover` / `intro` / `is_public` 三个**：**被否**（主人否掉封面图）。
- **只做前端、字段等以后再加**：**被否**——面板要真的能用，字段就得真的存下来；做成只在前端存在的字段等于假界面。

## Consequences

- **`is_public` 目前是「存而不用」的字段**：写出来只解决「面板里这个开关有地方落」。**它不产生任何可见行为**——公开的收藏夹别人仍然看不到（没有发现页、没有分享链接、题目可见性没变，仍是 ADR 0030 的私有模型）。⚠️ **这是有意留的位，不是遗漏**；真要让它起作用是独立一轮（涉及分享入口、别人的可见范围、题目本身的可见性校验），本卡不覆盖。文档与界面文案都**不许**暗示「公开后别人能看到」。
- **浮层可用玻璃的两个注意点**（凡真用 `.glass` 的地方要防）：
  1. **`prefers-reduced-transparency`**：`.glass` 已有降级（退化为近白实底），这条降级必须保留。
  2. **对比度**：玻璃底是半透明的，背后内容深浅不一。凡玻璃上放**长正文或表单**的地方，实际观感必须逐个看，不能只靠 token 值算——`.glass` 的 `.68` 不透明度就是为守住 AA 才从参照图的 `.28` 提上来的（见 `tokens.css` 注释）。
- **答题页面（作答中，`/quiz/:id`）是硬禁用区**：那里的浮层（确认框、下拉等）一律实底。这条不随「逐件自定」浮动。
- **存量浮层不强制迁移**：是否换玻璃逐件看实体预览定，没有迁移时限；「长正文弹窗（题目详情）× 玻璃」因此不再是必须解的矛盾——实底本来就是合法选项。
- **`DESIGN.md` / `tokens.css` / `docs/design/前端.md` 的材质口径要同批改**（口径散落正是 ADR 0006 的老问题）：材料语言表、`tokens.css` 的浮层注释、`前端.md` 材质一节——三处按本卡定案的新口径一起收敛，并写明「已用玻璃的只有收藏夹信息面板」这个落地事实。
- **`intro` 的长度上限是本项目第一个 200 数量级的校验**：现有最长为「分类名 64」。列宽 `VARCHAR(200)`，DTO 上 `@Size(max = 200)`，前端计数器同步。名字仍沿用 20 字上限（`FavoriteFolderSaveDTO` 的既有 `@Size`），**不动**。
- **不新增 `cover` 相关的表列 / 接口**：将来若要，按 ADR 0023 单独发版（带迁移）。
- **`is_public` 与 `intro` 的读写口径**：创建与编辑走同一个接口（`FavoriteFolderSaveDTO` 扩字段），VO 回填。⚠️ 两个新字段**不能加 `@NotNull`**——存量请求（含既有测试里的只传 `name` 的调用）会 400；按「缺省即默认值」处理（`isPublic` 缺省 `false`、`intro` 缺省空）。
- 这次改动**只碰 CRUD 与展示**，不动 ADR 0030 的核心模型：没有「未分组」、收藏仍是「至少属于一个夹」、默认夹不可删。
