# 测试系统分三层：单元 / 接口与服务集成 / 端到端

Status: accepted

quizzy 原来只有「纯 JUnit、不拉 Spring、不碰数据库」的单元测试，只覆盖判分与导入校验两处（见 [《测试》](../testing/README.md)）。本次把测试扩成**三层**，每层存在的理由是「它有一个别层问不出的问题」：

- **单元（已有）**——单个类的逻辑对不对。不拉 Spring、不碰库，因此 CI 与任意机器都能毫秒级跑完。
- **接口与服务集成（两形态，同一层）**——在真 Spring + 真 MySQL 上跑。**接口形态**走 HTTP，问的是契约、鉴权、**数据边界**；**服务集成形态**直接调 Service，问的是跨组件协作、事务与**多表状态一致**。用 **Testcontainers** 声明式起 MySQL 8，**挂独立 Maven profile**，`mvn test` 保持纯净。
- **端到端**——真浏览器从界面走完整业务链路，问的是「用户看得见的那条路通不通」。用 **Playwright**，**只在 CI 的一次性环境里跑**。

三层互补而非替代：接口测试抓不到「后端返回了但前端没渲染」（2026-10-03 那个判分反馈 bug 就是这一类），端到端抓不到「拿别人的 id 改写数据」这类边界；而两者都不该承担纯逻辑的枚举——那是单元测试的活。

## Considered Options

- **只做端到端，不建接口层**：省一层的工具链，但契约漂移与越权这两类问题只能靠界面间接撞——而 [ADR 0006](0006-bare-array-import-contract.md) 记的正是「契约与实现漂移且无人发现」的前科。
- **只做接口层，不建端到端**：更稳更便宜，但放弃「前后端契约断裂」与「界面行为」这两类只有真浏览器能看见的失效。
- **测试库用 CI service 容器**（照 `release.yml` 的临时 MySQL 写法）：与既有 job 心智一致、零新依赖，但**本机跑不了**——改代码时无法自查，与项目「随手能跑」的形态冲突。
- **测试库用 H2 内存库**：快，但方言与 MySQL 差异大，Flyway 迁移脚本未必跑得通——**在一个连迁移都要在真 MySQL 上重放的项目里，用 H2 等于把「测试环境与真实环境不一致」请回来**。
- **把端到端塞进 `quizzy-web`**：跨端（PC + H5 + 未来的小程序），塞进任何一个前端工程都会让那个工程被迫背起跨端职责。
- **本机也要求跑端到端**：本机 Docker Hub 不可达（[ADR 0010](0010-china-mirrors-for-build-deps.md)），且本机缓存会掩盖「干净环境才暴露」的坑（[ADR 0009](0009-glibc-build-image-and-dockerignore.md)）——**在 CI 之外再维持一套等价环境，成本高而保证弱**。
- **视觉回归截图比对**：见 Consequences 的最后一条。

## Consequences

- 仓库新增顶层目录 `e2e/`，**带独立 `package.json`**。两个前端工程的依赖树**不动**——原先「前端零单测、零 lint、零额外依赖」这条刻意选择（见 [《测试》](../testing/README.md)）**依然成立**，本次只新增一个独立测试工程，不是给前端加依赖。
- `quizzy-server` 新增 Maven profile；两层共用 `src/test` 树，靠 JUnit 标签区分。**默认 `mvn test` 只跑单元测试**——`docs/testing` 里「CI 上跑 `mvn test` 不需要起任何服务」这条约束必须继续成立。具体标签名与 profile 名以 `pom.xml` 为准，文档不复制。
- **端到端跑在 CI 的一次性环境**：`mysql:8` service + 后端进程 + 前端 preview + Playwright，跑完随 runner 销毁。测试专用配置**直接注入 job 的 env，不建 `.env` 文件**——避免出现第二份会漂的配置真相源（[ADR 0006](0006-bare-array-import-contract.md)）；这也正好解开 `ci.yml` 里「不敢 `compose up`」那个结。
- 前端源码要加少量 `data-testid`，**只加在「同一页会重复出现或文案会变」的元素上**（答题页选项、判定结果区、解析区），其余靠语义定位。
- `release.yml` **不加**测试门禁：CI 已在 master 上跑同一套，而 tag 必然建立在已绿的提交上；再跑一遍是重复烧 runner 并拖慢发版。真出现「CI 绿、线上坏」那是**环境差异**，测试在 CI 上跑也拦不住，归 `docs/operations/runbook.md`。
- **移动端 H5 本轮不纳入端到端**：移动端主线 2026-10-03 才走通、小程序编译目标与 `/m/` 部署未做，此时把端到端压上去会被两处改动同时拉扯。记在 `docs/todo/2026-10-03-TODO-移动端与小程序落地.md`。
- **明确不做，接受盲区**：视觉回归截图比对。理由三条——① 差异对业务正确性无影响且**人眼当场可见**，② 单人开发没有第二双眼睛去审基线，等于自己给自己签字，③ 基线是入库的二进制会持续膨胀，且 CI runner 无中文字体，基线永远对不齐。**代价是 UI 排版零自动化**，这一条明写在 [《测试系统说明》](../testing/系统说明.md)。
- 同样明确不做：跨浏览器矩阵（Firefox / WebKit）、把 AI 探索测试接进 CI 门禁。探索测试**不是测试**（不可重复、无断言），见 [《测试系统说明》](../testing/系统说明.md)。
- 测试文档受 [ADR 0006](0006-bare-array-import-contract.md) 约束：**规则数值（掌握阈值、字段名、响应信封形状）一律不复制进文档**，只指向 `ScoreStrategy` / `QuizService` / `/v3/api-docs`。测试断言也应从代码读阈值，不得硬编码——否则测试会变成第二份会漂的规则描述。
- 加测试的时机与内容由 [ADR 0021](0021-test-sync-discipline.md) 管。

## Amendment 1（2026-10-04）：排版不再「零自动化」——几何断言进门禁

正文 Consequences 里「**代价是 UI 排版零自动化**」这句不准确，需要收紧。根因是它把「排版」等同于「视觉回归截图比对」，而这两件事不是一回事。

**排版要拆成两类**：

- **几何事实**——横向溢出、元素越出可视区、文字被容器裁切。浏览器能直接给出每个元素的矩形框（位置与宽高），于是这些都是**纯数值比较**：**不需要基准截图、也不需要 AI 判断**。可重复，因此**能进 CI 门禁**。
- **审美与层级**——间距是否协调、视觉重心、主次是否分明、颜色对比够不够。这需要判断力，不是断言能表达的。

**改动**：端到端层增加**几何断言**，只覆盖第一类，且**只做低假阳性的检查**：

- **做**：横向溢出、元素越出可视区、文字被容器裁切；
- **不做：元素重叠检测**——下拉菜单、浮层、tooltip 本来就该重叠，做它会产生大量误报；而误报会让人养成「红了也照合」的习惯，那比不检查更糟（同 `check-doc-links.sh` 头部写的取向）；
- 视口只挑几个代表宽度（建议 1280 / 768 / 375），**不做全矩阵**。

**第二类的归属**：审美与层级判断仍靠人眼；AI 探索测试**顺手粗筛**（当真实用户走页面时记下「挤在一起」「看不出层级」这类现象）。它是报告制、不进 CI，**不能替代门禁**。

**视觉回归仍然明确不做**——正文那三条理由（单人没有第二双眼睛审基线、CI runner 无中文字体导致基线永远对不齐、二进制基线持续膨胀）一条都没变。本 Amendment 只是把「排版」里**本来就不需要基准图**的那部分拿回来做断言。

**顺带把正文两处措辞读准**：

- Consequences 的「代价是 UI 排版零自动化」应读作「**审美与层级判断零自动化**；几何事实由端到端层的断言覆盖」；
- 「明确不做」清单里的「视觉回归截图比对」**保持不变**——它**不等于**「排版不做测试」。

**决策过程**：主人于 2026-10-04 追问「UI 排版测试能不能交给 AI 探索测试」，发现原文把两个概念混为一谈，随后拍板「几何断言要做、探索任务书要加『看排版』一条」。

相关：[ADR 0021](0021-test-sync-discipline.md)（改动 → 补哪层的映射表里，「只改样式 / 文案 / 排版」那一行应按本 Amendment 理解为「**不补断言**，但几何断言若覆盖到该页面则自动生效」）。
