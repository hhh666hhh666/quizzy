# 移动端视觉统一到 PC 色板，关键交互件自绘

Status: accepted

移动端（`quizzy-mobile`）原先沿用 PC 端 2026-10-08 重建之前的 Element Plus 遗留色（`#409eff` 主色 + `#f5f7fa` 底，页面里还散着十来个硬编码色），与 PC 端重建后的新色板是两套。本卡定三件事：**色板复用 PC 那一套**、**交互件自绘到什么程度**、**对 / 错在答题页怎么表达**。

三版视觉稿由 Stitch 生成、主人挑定（产物在 `.workbuddy/stitch/`，不入库）。

## Considered Options

- **移动端另起一套更"App 感"的重色**（深底、立体卡片）：手机上更抓眼，但会形成**两份会各自漂移的色板**，与「一处事实一个来源」（ADR 0006）正面冲突，且 PC / 移动切换时割裂。否。
- **保留 `wot-design-uni` 全套组件，只覆盖它的主题变量**：改得最快，但它的圆角、间距、高亮色不完全听我们的，改到深处会撞墙，最后还是要自绘。否——只保留真正复杂的那几个（数字步进器、分类选择器、多选组）。
- **只换皮肤，不动结构**：见效快，但"答题页四个按钮分三行堆着、视觉重心落在『放弃本次』"这类结构问题改不掉，是本轮最想解决的。否。
- **复用 PC 色板 + 皮肤与结构一起改 + 关键件自绘**（选定）：色板只有一个真相源；按钮 / 选项 / 输入框这类简单件自己写，视觉才真正统一。

## Consequences

- ⚠️ **移动端写不了 `oklch`**：微信小程序内置浏览器不一定认，所以 `quizzy-mobile/src/uni.scss` 里落的是 `quizzy-web/src/styles/tokens.css` 的 **hex 换算结果**，换算表在 `.workbuddy/stitch/tokens-hex.json`（不入库，可重算）。
  **改颜色的顺序固定**：先改 PC 端 `tokens.css` → 按表换算 → 抄到移动端。反过来改等于又造一份真相。
- 移动端**只做浅色一档**（PC 端有深浅两档）：手机端跟随系统深色会使题干与解析的"近白阅读面"失效，本轮不做。
- **答题页的对 / 错**：选错的项染红、正确答案染绿（主人 2026-10-09 定）。⚠️ 颜色**从不单独表意**——同一屏始终配有「回答正确 / 回答错误」标题与「正确答案：X」一行，色盲与高对比模式下照样读得出来。结果页沿用同一口径。
- 「放弃本次」从整块危险色按钮降级为顶部文字链，底部操作条一屏只留**一个**主按钮。
- 题库 / 组卷 / 导入导出仍然只在 PC（ADR 0019），本卡不动这条边界——移动端本轮新增的错题本、答题记录、试卷三页都只是**只读消费**。

## Amendment 1（2026-10-10）：答题页按挑中的 V1 稿复刻

原卡落地后发现与设计稿（Stitch V1，主人挑定）有偏差，主人对照截图指出后修正：

- **两枚浅档 token 为「设计稿直采」，不进 PC 换算表**：复刻时从 V1 设计稿像素采样得到
  `$app-brand-wash: #eaf2ff`（选项整行选中洗底，比 brand-soft 更浅）与 `$app-divider: #f0f4f8`
  （卡内细分隔线）。两者只服务移动端这一处用法，**不反向进 PC 端 `tokens.css`**；其余色值仍守
  「PC 换算表」纪律（见 Consequences 第一条）。
- **答题页顶栏改为自绘浅色品牌头**：`navigationStyle: custom`，行内「quizzy」字标 + 「放弃本次」文字链
  （V1 稿的头部形态，系统导航栏给不了这个排版）。**其余页面暂保留系统导航栏**——设计稿只覆盖答题页，
  且子页面需要返回入口；统一与否见 `docs/todo/`。
- **判分标记语义收口**：勾只表「对」（✓）、叉只表「错」（✗）、选中态画白点——此前「选中即画勾」，
  在答错时把错选项标成了勾，语义是错的。
