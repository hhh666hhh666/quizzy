# 注销账号 = 硬删，且不留悬挂引用

Status: accepted

账户自助这轮要加「注销账号」。项目里 `question` 是唯一用逻辑删除（`deleted` 标记）的表，其余都是物理删。注销这条路径选**物理删除**：`user` 行连同他的题目、选项、标签关联、试卷、试卷题目、作答统计、会话、作答一起真删。

## Considered Options

- **软删账号（`user` 加 `status` 字段）+ 删数据**：登录被拒、用户名永久保留。被否，但**它有一个真实的好处**：那个字段正好可以复用为 [ADR 0017](0017-public-signup-service.md) 承诺的「最小封禁开关」。之所以仍然否掉，是因为「注册风控」这轮已被明确划在范围外，借注销顺带把一个安全字段塞进来，会让两条独立的线互相纠缠。
- **软删账号且数据全留**：只停登录，什么都不删。改动最小，但「注销」名不副实——对公开服务而言这不叫删除。
- **硬删（选定）**：语义最直白，用户名立即释放、可以重新注册同名。

## Consequences

- ⚠️ **不可逆**，所以必须配二次确认（输当前密码），且前端要明确列出「将永久删除 X 道题、Y 条作答记录」。项目目前**没有调度器**，做不了「冷却 7 天再真删」——那会是又一块基础设施。
- **题目跟着物理删，而不是沿用项目现有的软删**：软删是为了保住「历史一致性」——会话历史引用过的题不能凭空消失（见 [《数据模型》](../design/数据模型.md)）。注销时他的会话与统计也一起删了，没有任何东西再引用那些题行，软删的理由消失，只剩 `owner_id` 指向一个已不存在用户的悬挂行。所以这里物理删。
- 清理必须在**一个事务**里完成：库里没有任何外键，也就没有任何数据库级级联兜底，漏一张表就是脏数据。
- 注销**只影响他自己那一套**：他无法把自己的私题转成公开题（[ADR 0003](0003-public-questions-by-empty-owner.md)），别人也无法把他的私题加进自己的卷（`PaperService.requireVisibleQuestions`）——所以不存在「删了他，别人的东西挂掉」的情况。
