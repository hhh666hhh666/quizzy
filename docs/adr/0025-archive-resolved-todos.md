# 已结案的待办移入 `docs/todo/archive/`

Status: accepted

`docs/todo/` 按主题拆文件，但主索引表把「待办」与「已解决」混在一张表里。随着结案件数增加，主表只会越拉越长——每次想看清「还剩哪些没定」，都得先把已结案的看完。现定：**一条待办的 `状态` 变成 `已解决`，就 `git mv` 进 `docs/todo/archive/`**，主索引表相应地把该行从主表移到独立的「已归档」区。

## Considered Options

- **就地改状态、文件留在 `docs/todo/` 不动**（原做法）：改动最小。**被否**——已结案与未决混列，主表长度只增不减，「还有什么没定」这个唯一诉求被稀释；且结案文件与未决文件同目录，光看目录分不出哪些还在等。
- **结案即删除文件**：主表最干净。**被否**——丢了「当初纠结过什么」的价值。`2026-10-05-TODO-历史作答统计重复计数.md` 那类记录，明确是为了「下次看到同一现象别再当新 bug 查」而留的，删了就没了。
- **移入 `docs/todo/archive/`**（选定）：主表只留未决项，已结案的按创建日期成堆留在子目录里；要查背景仍查得到，又不占主表。

## Consequences

- **主索引表分两段**：主表只列未决项，「已归档」区列结案项。某条结案时，两处要一起动。
- ⚠️ **归档时相对链接要退一层。** 文件从 `docs/todo/` 移到 `docs/todo/archive/` 后深了一层，文内所有 `../` 链接都要多退一级（`../adr/…` → `../../adr/…`、`./README.md` → `../README.md`、`../README.md` → `../../README.md`），否则 `scripts/check-doc-links.sh` 会在提交前报红。这是每次归档的**固定动作**，已写进 `docs/todo/archive/README.md`。
- **文件名不变**：日期是**创建日期**（见 `docs/todo/README.md`），归档不改名。
- **规则同步**：归档从「一次性动作」升级为**常驻纪律**，写进 `.codebuddy/rules/todo-discipline.md` 与根目录 `AGENTS.md`。
