# quizzy 从个人工具变成对公网开放的注册制服务

Status: accepted

`docs/requirements/scope.md` 原先给 quizzy 的定位是「**个人自学的刷题工具**」，运行形态也是纯本机 `localhost` 自用。本次把它改成对公网开放、**任何人注册即可使用**的服务：跑到一台阿里云 ECS 上，绑已备案的域名，走 HTTPS。这不是加一个部署目标，而是产品定位变了——它同时带来「用户不是我自己」和「出事要我自己兜」两件事。

## Considered Options

- **只自己用，靠隧道 / IP 白名单访问**（改动最小、安全面最小、不必备案）：实现上完全可行，但放弃了「分享给同学一起刷题」这件事，而那正是搬到常驻机器上的动机。
- **邀请制，关闭公开注册**：门槛适中，仍然需要域名、备案与 HTTPS。被否是因为没有现成的邀请机制，而在注册接口上加一个邀请码，与直接加限流的工作量差不多。
- **公开注册 + 准入门槛**（选定）：保留公开注册，但**不裸奔**——图形验证码、注册接口按 IP 限流、一个最小的账号封禁开关。邮箱验证属同一决定的一部分，但**推迟到部署链路跑通之后单独做**（见 Consequences）。

## Consequences

- **`docs/requirements/scope.md` 的「产品定位」与「明确不做」都要改。** 定位那句「个人自学的刷题工具」不再成立；「明确不做」里原有的「后台用户管理与角色权限（RBAC）」仍然不做，但**必须补一个例外**：公开站点需要封禁滥用账号与删除违规内容的能力，否则出事时只能上数据库手删。这个例外刻意做得很小——一个布尔字段级的封禁开关，不是权限体系。
- **合规从「不涉及」变成「义务」**：中国大陆服务器用域名对外服务需 ICP 备案（ECS 须包年包月且剩余 ≥ 3 个月），备案通过后 30 日内还要办公安备案。**备案是本次上线唯一不可压缩的关键路径**（约 1–3 周），必须最先启动。
- **一批「本机自用才成立」的简化项全部失效，且是同时失效**：`MYSQL_ROOT_PASSWORD=123456`、后端 8080 直接暴露、`WebConfig` 里 `allowedOriginPatterns("*")` 与 `allowCredentials(true)` 并存、全链路 HTTP、无注册风控。`docs/decisions/docker-run-setup.md` 的 D3 当时已经预警过这一点（「哪天要放到能被别人访问的环境，密钥和端口映射必须重来一遍」），这里是那笔账的到期日。
- **邮箱验证被推迟，但它不是「以后再说」而是一次已排期的功能开发**。已记录的偏好是「邮箱作为登录名、用户名降为昵称、SMTP 用现有个人邮箱」。⚠️ **这三条放在一起有冲突**：邮箱即登录名意味着「收不到验证信 = 登不进来」，而个人邮箱 SMTP 恰恰是最容易进垃圾箱、且有发信限额的通道。做到那一步时要重新评估发信通道。未决事项见 [`docs/todo/2026-10-01-TODO-邮箱验证.md`](../todo/2026-10-01-TODO-邮箱验证.md)。
- **运维责任变了性质**：从「挂了就挂了，重启一下」变成「挂了有人会看到」。备份从「锦上添花」变成「唯一副本的保护」，且原来「备份与数据同在 E 盘」的伪备份问题随之上移到 OSS。相关处置流程见 `docs/operations/`。
