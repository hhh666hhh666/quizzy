# 批量导入跳过错误行，其余照常入库

导入时逐条校验，不通过的行单独跳过，最后返回总数、成功数和逐行错误报告（行号、题干、原因）。手工整理或从文档生成的表格几乎必然有错行，全量回滚会逼着人为了三行脏数据把整张表改二十遍再重新导入。

## Considered Options

- **整体事务回滚，一条错就全不入库**：数据最干净，但导入体验极差——错误往往改完又冒出新的，来回拉锯。
- **先全量校验、全部通过再入库**：看着兼顾，实际要跑两遍校验逻辑，而且大批量导入时用户要多等一轮。
- **跳过错误行 + 逐行报告**（选定）：一次导入能救回绝大多数题，代价是明确的——错误行需要用户自行修正后重导。

## Consequences

- 导入不是原子操作，中途可能有部分数据已入库。这是有意为之，不要「顺手」把它改成事务。
- 错误报告必须带行号，否则用户没法定位；Excel 导入的行号与表格行号对齐（数据行从 2 开始）。
- 分类与标签在导入时自动创建、同名复用，所以标签必须收敛，否则一次导入就能把全局标签库污染掉。
