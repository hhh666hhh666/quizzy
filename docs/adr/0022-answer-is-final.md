# 一题一答：已作答的题只能回看，不能再改

Status: accepted

一次会话里的每道题**只能提交一次**。提交后立刻拿到对错、正确答案与解析，但答案就此定稿——再翻回这道题只能**看**（题干、自己的选择、正确答案、解析），不能再选。想重做就另开一次练习（错题重练、重新抽题，或再发起一次试卷答题）。

**为什么**：这个工具的核心是「把不确定的题筛出来反复练」，而它靠两件事成立——即时反馈，以及一份**可信的作答统计**。允许回改会把两件事同时毁掉：

- 判完就把正确答案摆出来了，能改就等于「看一眼答案再改」。分数与正确率从此不再是真实水平，自己骗自己。
- 作答统计（`question_stat`）是**错题本题目的唯一来源**。同一题答两次会把它计数两次；更糟的是「答错 → 点亮错题本 → 改成正确 → 标记被抹掉」——「哪道题没掌握」这个信号当场丢失。

这不与 [ADR 0001](0001-practice-not-exam-semantics.md) 的练习语义冲突：练习语义要的是「即时反馈 + 错题反复练」，而回改恰好破坏这两点。它也不是考试语义的回归——没有限时、没有监考，只是在说**一次会话 = 一份作答记录**。

⚠️ 边界：「一题一答」管的是**改**，不是**答**。**跳过的题回头再答照样允许**，断点续答（[ADR 0002](0002-answer-progress-in-mysql.md)）不受影响——那是在补全这次作答，不是在修改已经定稿的作答。

## Considered Options

- **允许回改、以最后一次为准**（改动前的实际行为）：污染统计，而且「看了答案再改」让正确率失去意义。补充一个事实：前端**从来**没允许过——提交后选项即禁用、按钮变「下一题」（PC 与移动端都是），只有后端没拦，文档与接口测试也一直写着「可回退改答案」。三处口径不一，这次是把它对齐到前端早已实现的行为。
- **回改时撤销上一次的统计**：要回滚的是 `question_stat` 上的累加值，但那张表只存当前状态、不存历史，撤不干净；而且「撤销」本身也解不了「看了答案再改」。
- **只在前端禁用，后端不校验**：接口是公开的（`POST /api/quiz/sessions/{id}/answer`），直接调、双开页面、旧版缓存的前端都能绕过去。这正是改动前的实际状态。
- **已作答的题彻底不再展示**：回看是练习的主要用法之一（做完整套再逐题看解析），藏掉等于砍功能。

## Consequences

- 接口层于是有两种拒绝，都在 `QuizService#answer` 里：**会话已结束**与**题目已作答**。两者都是 `BusinessException`（业务码 1000）。前端两条都到不了，但接口必须拦。
- 判据是 `user_answer` 非空——**必须与 `QuizService#detail` 里算 `answered` 的那句保持一致**，否则会出现「界面显示未作答、接口却拒绝提交」这类自相矛盾的状态。
- **历史统计里的重复计数无法回溯修正**：覆盖写在 `quiz_answer` 那一行上，被覆盖的次数没有留痕，算不出来。已有偏差只能留着，记在[那条待办](../todo/archive/2026-10-05-TODO-历史作答统计重复计数.md)。
- 测试里少了一种造数手法——「同一道题先当答错的样本、再改成答对」。要造「一对一错」得用两道题（见 `QuizApiIT#finishIsConsistent`，它改成显式抽 3 道，并在用例内从库里取正确答案）。
- 回看时**要能看到正确答案与解析**，否则已作答的题既不能改、又学不到东西。PC 与移动端必须同步（[ADR 0019](0019-mobile-clients-with-uniapp.md)）：两端都在回看时只读展示正确答案与解析，并给出「本题已作答，答案不可修改」的提示。
