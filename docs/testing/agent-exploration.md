# AI 探索测试 · 任务书

**这份文件不是测试代码，是给一次会话的「任务书」**：由主人手动唤起一个 AI，让它像真实用户一样把系统用一遍，**产出报告**而不是断言。

**为什么单独一份**：探索测试**不是测试**——不可重复、不产出断言、不能进 CI 门禁，定位见 [《测试系统说明》的「探索测试」一节](./系统说明.md#探索测试不是测试)。

**怎么触发**：主人自己发起，把本文件交给要执行的那次会话。**不接 CI、不做定时。**

## 0. 这份文件是自包含的

⚠️ 执行它的 AI **可能来自任何平台**，所以：

- **不要假设能自动读到本项目的规则文件**。项目纪律放在 `.codebuddy/rules/`，但那套自动加载机制**只在部分工具里生效**；跨工具摘要见根目录 [`AGENTS.md`](../../AGENTS.md)。本文件把该读的东西**显式列在下面**，不依赖任何自动加载。
- **开工前先做能力自检**（下一节），缺哪项就在报告里**声明**缺了它，**不要默默跳过**。让主人拿到一份看起来完整、实际少一半的报告，比做不了更糟。

### 能力自检

| 能力 | 用来干什么 | 缺了怎么办 |
|------|------------|------------|
| 读文件 | 读下面那几份真相源 | 做不了，直接说明 |
| 执行命令 | 起 MySQL、起后端、起前端 | 做不了，直接说明 |
| 驱动浏览器（点击、填表） | 走完整条业务链路 | 做不了，直接说明 |
| **截图 + 能看图** | 判断「挤在一起」「看不出层级」这类排版现象 | **只有「顺手看排版」那一条做不了**，在报告里声明 |

## 1. 开工前先读这些（不要靠本文档转述）

本文档**刻意不复制任何规则数值与字段名**——复制进来的派生事实必然漂（[ADR 0006](../adr/0006-bare-array-import-contract.md)）。先读这四处，把「什么算对」搞清楚：

| 要搞清什么 | 去哪读 |
|------------|--------|
| 产品定位与**明确不做** | [《需求范围》](../requirements/scope.md) |
| 判分、会话、错题本、抽题规则的语义 | [《判分与业务规则》](../design/判分与业务规则.md)（**具体阈值以代码为准**，文档不写死数字） |
| 每个词的准确含义 | [`CONTEXT.md`](../../CONTEXT.md) |
| 当前真实的接口清单与字段 | 后端起好后的 `/v3/api-docs` 与 `/swagger-ui.html`（**不要看任何静态文档**） |

## 2. 环境：本机 dev，专用测试账号

测试对象是**本机的开发形态**：`docker-compose.dev.yml` 起 MySQL，后端 `mvn spring-boot:run`，前端 `npm run dev`。跑法以 [根 `README.md`](../../README.md) 的快速开始为准。

**账号约定（必须遵守）**：用**本次会话专用的测试账号**注册，用户名带固定前缀便于事后识别与清理：

```
explore_<YYYYMMDD>_<HHmm>
```

**红线（违反即停）**：

1. **绝对不要连云端 prod 库**。生产库的 3306 绑在服务器回环上、专门给 SSH 隧道留了口子（见 [《部署》](../operations/deployment.md)），隧道一通就够得着——这是本项目最真实的暴露面。
2. **不要动这个测试账号之外的数据**：不改别人的题目、不删任何东西、不清库。
3. **发现异常先停再报**，不要顺手去改代码。探索的产出是**报告**，不是补丁。
4. **不要提交任何代码**。

⚠️ 本次探索会往 dev 库留下测试账号、题目与会话记录，**跑完不会自动消失**（清理方式尚未定，见 `docs/todo/2026-10-04-TODO-测试系统落地.md`）。接受这一点再开工。

## 3. 任务：做一个「刚注册的普通用户」

以一个**从没用过这个站的普通用户**身份，把下面这条链路走完（这是主线，不是全部）：

**注册 → 登录 → 建题（至少一道多选）→ 组卷 → 开始答题 → 提交看判分与解析 → 结算 → 看错题本 → 再练一遍**

目标端默认是 **PC 端**（`quizzy-web`）；移动 H5（`quizzy-mobile`）可作为第二轮目标，不强制。

## 4. 顺手看排版（能力允许时必做）

这一条是**几何断言之外的补充**——端到端层的几何断言只能查「溢出 / 越界 / 裁切」这类数值事实，**审美与层级它表达不了**（见 [《测试系统说明》](./系统说明.md#排版怎么测三类分工)）。探索时顺手把这类现象记下来：

- 元素挤在一起、间距明显不均、看不出主次层级；
- 文字被遮挡、按钮不像可点、提示文案像正文；
- 移动端出现横向滚动条（**注意**：横向溢出本是几何断言的活，这里只是顺手一并记）。

⚠️ 判定要有依据：**先看清当时的视口宽度**，并在报告里写出来。**不要凭感觉报「错位」**——假阳性会让人不再信任报告。

## 5. 探索自由度：明确许可「乱来」

这是探索测试区别于脚本测试的**核心价值所在**——下面这些**是被鼓励的**，不是越界：

- 空输入、超长文本、特殊字符、纯空格；
- **连点两次提交**、提交后立刻刷新页面、中途关掉再打开；
- 乱序操作：先结算再想改答案、先看错题本再答题、跳过题再回头答；
- 故意选错、故意多选、故意少选（验「全对才得分」这条规则的**反例**）；
- 刷新 / 后退 / 直接改地址栏里的 id；
- 尝试访问**不属于本账号**的资源（看别人的题目 id、别人的会话 id）——**这是最值得探的一块**，看服务端的数据边界挡不挡得住。

## 6. 步数上限

**最多 N 步（建议 60～80 步）就收工出报告**，不要为了「再多试一下」无限循环。到上限还没走完主线，就在报告里写明走到哪、为什么没走完。

## 7. 报告写到哪

**报告写到仓库根下的 `.workbuddy/exploration/`**，文件名沿用会话记录的样式：

```
.workbuddy/exploration/<YYYY-MM-DD>-<HHmm>-<短ID>.md
```

**为什么是那里**：该目录**已被 `.gitignore` 排除**（属本机数据、不入库），于是报告既在项目里、又不会污染仓库。判据是「**写到一个不进 git 的本地目录**」——若那个平台没有 `.workbuddy/` 这个约定，位置可自行选，但必须在**报告开头写明实际路径**。

⚠️ **报告不进仓库、不写成文档链接**。仓库里只留**能固化的东西**（见下一节）。原因：报告描述的是「探的那天系统怎么表现」，代码一改就陈旧——留一份会过期的副本正是 [ADR 0006](../adr/0006-bare-array-import-contract.md) 的失效模式。

## 8. 报告格式（产出物）

开头先写**实际路径**与**能力自检结果**（哪一项没做、为什么）。之后每条问题一段，四行齐全：

```markdown
### 问题 N · <一句话现象>
- **期望**：<按上面第 1 节读到的规则，本该发生什么>
- **实际**：<实际发生了什么，附页面上的原文>
- **复现步骤**：<编号步骤，能照着再走一遍；排版类问题要写清当时的视口宽度>
- **严重度**：阻断 / 严重 / 一般 / 观感
```

**没有发现异常也要出报告**，写清「走了哪些路径、哪些是意料之中的、哪些当时没看懂」。

## 9. 收尾：把留得住的东西交出来

探索撞到的问题，**下一次不一定还能撞到**——所以要回写成 spec 才留得住（[ADR 0021](../adr/0021-test-sync-discipline.md)）。报告末尾必须补两节：

1. **建议固化为端到端 spec 的问题**：哪些现象值得写成一条自动跑的 spec。按「改动 → 补哪层」的表（在 [《测试系统说明》](./系统说明.md#加新功能时如何同步)）判断该进哪一层；**排版类**则判断该写成几何断言（溢出 / 越界 / 裁切），还是只能留给人眼。
2. **建议进 `docs/todo/` 的线索**：本次没能力定论、但值得记下来的东西（未定的口径、可疑但未复现的现象）。
