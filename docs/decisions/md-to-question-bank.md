# 决策日志：做一个「markdown 知识库 → 题库 JSON」的 skill

## 2026-09-18 16:47 · 第 1 次 grill

起因是「我想做一个 skill，根据 markdown 知识库文档自动生成 json 题库」。开问前先派了一个探查子任务摸仓库，
拿到三条决定性问题边界的事实：① `quizzy-server` 已有完整题目模型，题型只有 `SINGLE/MULTI/JUDGE`，
**没有 knowledgePoint 字段**，知识点靠 `category` + `tags` 表达；② 导入接口 `POST /api/questions/import/json`
收的是**裸数组**，而 `DESIGN.md` 8.2 节写的包装对象与实现不一致；③ 仓库里**既没有 markdown 知识库、
也没有 JSON 题库样例**——所以输入约定（文档长什么样）必须由这个 skill 自己立规矩。

本轮分两批问：Q1–Q6 在 16:12 收口，Q7–Q12 在 16:47 收口。两次用户都答复「都按你推荐的来」，
即全部采纳推荐项。设计树走完后当场实现，同一会话内跑通全链路（含两条故意埋的错题被拦截）。

### D1 · 定位为 quizzy 专用，产物直接吃导入契约

- **决策**：skill 只服务 quizzy，输出**裸数组** `[QuestionImportDTO]`，字段严格对齐服务端 DTO；溯源信息不进导入 JSON，另存旁车文件。
- **因为**：采纳推荐。它长在这个仓库里、导入接口已存在，直接产出可导入的东西零摩擦，字段约束天然被服务端校验兜住；旁车文件补回"通用格式"才有的元信息，两边兼得。
- **放弃**：产出中立题库格式（带 `meta/version/source` 包装、支持填空问答等扩展题型）再写转换脚本——把题型锁死在 `SINGLE/MULTI/JUDGE` 之外的表达力，v1 用不上。
- **来源**：Q1
- 相关：[ADR 0006](../adr/0006-bare-array-import-contract.md)

> **Q1 - 这个 skill 是 quizzy 专用，还是通用的？**：产物是**直接对准 quizzy 的导入契约**（裸数组、字段严格对齐 `QuestionImportDTO`、生成完可以直接贴进前端 `ImportDialog` 或 curl 打接口），还是产出一个**中立题库格式**（比如带 `meta/version/source` 包装、支持填空/问答等扩展题型），再靠一个转换脚本适配 quizzy？
>
> ➡️ 推荐：**quizzy 专用**。既然它长在这个仓库里、且已有导入接口，直接产出可导入的裸数组，同时额外写一个 `.meta.json` 旁车文件记录溯源信息（每道题来自哪个文件的哪个章节），两边兼得。
>
> **你的回答**：这几个问题都按你推荐的来

### D2 · 知识库文档约定走兼容式

- **决策**：`category` 优先取 frontmatter，缺失时取一级目录名，再缺取一级标题；`tags` 同理，路径/文件名/章节名 + 正文术语兜底。
- **因为**：采纳推荐。当时知识库还不存在，任何强约定都会变成"你得先整理文档才能用"的门槛；兼容式允许把一堆现成 md 直接丢进去就跑。
- **放弃**：强制 frontmatter（表达力最强但要先改造文档）；完全不约定（自由出题、不保证章节覆盖）。
- **来源**：Q2

> **Q2 - 知识库 markdown 怎么组织？**（决定了 skill 怎么定位"一章"、怎么推断 category/tags）
>
> A. frontmatter 优先：每个 md 顶部写 `category`、`tags`、`difficulty`，正文用 `##` 分节／B. 目录结构优先：`docs/Java并发/volatile.md`，目录名即 category，文件名即主 tag／C. 两者兼容：frontmatter 有就用，没有就从路径和标题推断／D. 不约定：随便什么 md，自由出题
>
> ➡️ 推荐：**C（兼容式）**，默认走 B 的路径推断，frontmatter 存在时覆盖。
>

### D3 · 生成机制 = 脚本切分 + 模型出题 + 脚本校验

- **决策**：Python 脚本按章节切片并生成任务清单，agent 逐片出题落盘，最后脚本跑 schema 与业务规则校验，不合格的打回重生成。
- **因为**：采纳推荐。题库真正的风险不是"生成不出来"，而是"生成了一堆错答案还不自知"——多选题答案集合、判断题对错，模型很容易写错且不会自己发现，必须有脚本做硬校验。
- **放弃**：纯 prompt 驱动（大文档会爆上下文、格式全靠模型自觉）；纯规则化抽取（题目机械且同质化严重）。
- **来源**：Q3

> **Q3 - 生成机制走哪条路？**
>
> A. 纯 prompt 驱动／B. 脚本切分 + agent 出题 + 脚本校验（含选项数、答案合法性、难度枚举、重复题干检测，报错打回重生成）／C. 规则化抽取（从定义句、对比表格、"注意/坑"段落套模板）
>
> ➡️ 推荐：**B**。必须有脚本做硬校验这一环。
>

### D4 · 每章 3–5 题，只对有实质信息的段落出题

- **决策**：默认按章节出题、每节 3–5 题，支持参数覆盖总数；凑不出题就少出或不出，不硬凑。
- **因为**：采纳推荐。按字数换算会逼着模型给废话段落编题，那是错题的主要来源。宁可少出，不可硬凑。
- **来源**：Q4

>
> ➡️ 推荐：**默认按章节，每章 3–5 题，且只在有实质信息的段落出题**；支持命令行参数覆盖总数。

### D5 · 题型配比：单选 60% / 多选 25% / 判断 15%

- **决策**：默认按此配比出题，可用参数调整；判断题固定两个选项（正确/错误）。
- **因为**：采纳推荐。单选是刷题主力且答案唯一、最不容易出错；多选判分要求集合完全一致，占比太高会显著拉高挫败感；判断适合覆盖易混点，少量点缀。

> ➡️ 推荐：**单选 60% / 多选 25% / 判断 15%**，可用参数调。

### D6 · 增量幂等做到"轻实现"，标识放旁车文件

- **决策**：不做全量覆盖；用题干指纹 + 来源章节做 diff，重跑默认只追加新题并报告已存在的题。
- **因为**：采纳推荐。全量重生成会冲掉手工改过的题，且题目标识不稳定。
- **放弃**：每次全量重生成、覆盖输出文件（简单，但人工修订会丢）。
- **来源**：Q6
- 后果：稳定标识写进 `.meta.json`／`.full.json` 旁车文件，不污染导入 JSON——`QuestionImportDTO` 本来也没有 id 字段可用。

> **Q6 - 要不要支持增量与幂等？**
>
> A. 每次全量重生成、覆盖输出文件／B. 增量：用「源文件路径 + 章节标题 + 题干指纹」生成稳定标识，比对已有题库，人工改过的题标记 `locked` 跳过／C. 不做，单次任务而已
>
> ➡️ 推荐：**B，但用轻实现**——稳定标识写进旁车的 `.meta.json`，用「题干指纹 + 来源章节」做 diff，重跑时默认只追加新题、报告已存在的题。

### D7 · 难度按认知层次推断，分值跟难度走

- **决策**：记忆型（是什么/定义）=EASY、理解型（对比/为什么）=MEDIUM、综合型（场景判断/多因素/坑）=HARD，frontmatter 写了以它为准；分值 EASY 1 / MEDIUM 2 / HARD 3。
- **因为**：采纳推荐。多选题天然更难，但一刀切设成 HARD 会导致"简单的多选"被高估；分值跟难度挂钩，是为了组卷时按难度抽题有意义。
- **放弃**：全默认 MEDIUM／只按题型映射难度。
- **来源**：Q7

> **Q7 - 难度和分值怎么标？**：A. 全默认（MEDIUM、1 分）／B. 按题型映射（单选=易、判断=易、多选=难）／C. 模型按知识点复杂度推断，frontmatter 覆盖，分值跟难度 1/2/3／D. 只在 frontmatter 里显式写才标
>
> ➡️ 推荐：**C，frontmatter 覆盖**。
>
> **你的回答**：都按你推荐的来

### D8 · 标签必须收敛，宁可粗不可泛滥

- **决策**：`category` = frontmatter > 一级目录名 > 一级标题（兜底"未分类"）；`tags` = frontmatter > 文件名 + 所在 H2 章节名，再补 1–2 个正文领域术语（优先代码块语言名、反引号术语），**总数 ≤5**，小写归一、去重。
- **因为**：采纳推荐。quizzy 的标签是全局共享、同名复用的，标签太碎会污染整个标签库，以后筛选时满屏一次性标签。
- **来源**：Q8
- 后果：实现为"超过 5 个给警告、超过 10 个（服务端硬上限）判失败"，即软约束而非硬拦截。

> **Q8 - category 和 tags 的推断规则，要多细？**
>
> ➡️ 推荐：`category` = frontmatter > 一级目录名 > 一级标题，缺失兜底 `"未分类"`；`tags` = frontmatter > 文件名（去扩展名）+ 所在 H2 章节名，再补 1–2 个正文术语，总数 **≤5**，小写归一、去重。理由是标签必须收敛——宁可粗，不可泛滥。
>

### D9 · 答案正确性靠"原文溯源 + 干扰项检查"，模型自审默认关

- **决策**：格式校验之外，每道题必须带 `source_quote`（原文原句 ≤200 字），脚本回原文做字符串比对，找不到直接判失败并隔离；另做干扰项合理性检查（重复、过短、与题干相同、区分度弱）。
- **因为**：采纳推荐。原文溯源把"模型说它对"变成"原文里确有此句"，这是真正的硬防线；模型自审常常顺着自己刚才的思路再错一遍，性价比不高，但留成开关。
- **放弃**：只做格式校验（快但拦不住内容错误）；自审作为默认环节（耗时翻倍、效果差）。
- **来源**：Q9
- 后果：刻意选择"宁可误杀"——模型把原文改写一下就会被判失败，这是有意为之。

> **Q9 - 答案正确性的防线设多高？**（本轮最关键的一题）
>
> A. 只做格式校验／B. 格式校验 + 原文溯源（每道题附 `source_quote`，脚本逐题回原文做字符串包含检查，找不到判失败）／C. B + 自审一遍（以"阅卷人"身份独立重做，不一致的隔离）／D. B + 干扰项合理性检查
>
> ➡️ 推荐：**B + D，C 作为可选开关（默认关）**。
>
> **你的回答**：都按你推荐的来

### 本次定下的叫法

这几个都是这个 skill 的内部术语，不是 quizzy 的领域概念（题目、会话、错题本那些）。按 `CONTEXT.md` 的定位它只收领域术语，**不建议塞进去**。

- **切片（task）** = 一个出题单元，按 H2 切出来的一节；过长时再按段落二次切分成多片。
- **溯源（source_quote）** = 支撑正确答案的原文原句，逐字照抄、≤200 字，是防幻觉主防线。
- **指纹** = `sha1(归一化题干 + 题型)`，判定"是不是同一道题"的依据。
- **修订** = 指纹未命中、但题干相似度 × 50% + 选项内容重合度 × 50% ≥ 0.75 且题型相同的旧题，会被新版本替换。
- **锁定（`_locked`）** = 人工改过的题，重跑时永不覆盖。
- **旁车文件** = 与导入 JSON 并存的 `.meta.json` / `.full.json`，存溯源与指纹，不进导入请求。

- **决策**：每题**必须**给一个考频档位（缺失或给两个以上判硬失败）；`高频` 不超过总题数 30%，超了只告警；中频/低频**不设配额**；分布进 `review.md`。
- **因为**：采纳推荐。**强制分布会逼模型为凑配额改编档**——那和第一轮 Q4 否掉的"按字数硬凑题"是同一种病。三档里只有"高频"有行动含义（刷题时的动作是"先刷高频的"，不会专门去刷低频），所以只锁这一档。
- **放弃**：C「不必标，未标的算中频」——看似省事，但把"中频"变成了垃圾桶，三档退化成两档。
- **来源**：Q13

> **Q13 - 三档的严格度怎么定？**

> A. 必标三选一 + 只锁高频上限（高频 ≤30%，越界警告），中频/低频不设配额，分布只在 `review.md` 里显示／B. 必标三选一 + 三档都设区间（高频 20–30%、中频 40–60%、低频 15–35%）／C. 不必标，未标的在统计时算作中频

> **你的回答**：Q13 选 A

### D13 · 单节题数不设硬上限，改成告警阈值

- **决策**：不设硬上限（不裁剪超出的题）。把原来的 `--per-section`（一个"建议配额"，默认 4）改成 `--max-per-section` 告警阈值（默认 5），单节超过只在 `review.md` 里标出来。
- **因为**：采纳推荐。它贴合用户"不要人为配额"的取向——不给配额，只给"这里有点多，你看一眼"的信号。C（上限随字数浮动）看着最科学，但那是**按字数推配额**，正是第一轮 Q4 否掉的东西。
- **放弃**：B「硬上限 5，超了直接裁掉多出的题」。

### D14 · 考频标签不占内容标签配额

- **决策**：内容标签仍 ≤5 个（超出警告），考频档位算元标签**不占这 5 个**；标签总数受 quizzy 硬上限 10 约束（5 + 1 = 6，安全）。校验器把两个告警拆开。
- **因为**：采纳推荐。不拆开的话每题都会撞"标签超过 5 个"的警告，那这个警告就废了。B（内容标签降到 4）是拿内容表达力换一个元标签的位置；C（混在一起提上限）以后看警告不知道是哪一类超了。

### 本次定下的叫法

这些依然是 skill 的内部术语，不是 quizzy 的领域概念。按 `CONTEXT.md` 的定位它只收领域术语，**不建议塞进去**。

- **学科工作区** = `question-bank/`，一个学科一个目录；`<学科>/md/` 是源、`<学科>/json/` 是产物。
- **知识点驱动** = 一节里有几个可考点就出几题，不设配额；单节题数只做告警不做裁剪。
- **考频三档** = `高频` / `中频` / `低频`，必标三选一；是**元标签**，不占内容标签的 5 个配额，总数仍受 quizzy 的 10 个上限约束。
- **判据锚定原文** = 只接受能从原文观测到的信号（被单列成标题、被加粗、跨节复现），禁止"据我所知面试爱考"这类先验表述。
- **跨学科不可比** = 考频三档只在同一份素材内部有可比性；"MySQL 的中频"和"Java 并发的中频"不是一把尺子量的。
- **单节题数告警阈值（`max_per_section`）** = 默认 5，超了只在复核报告里标出，**不是配额**。
